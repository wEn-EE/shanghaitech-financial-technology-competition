# 第18章 数据清洗、异常处理与质量审计

> 全章程序使用SYNTHETIC人工数据。沿用四类资产标识，但不将模拟价格、缺失率和异常率解释成真实市场规律。正文中的“时间步”是抽象等距观测网格，不代表真实交易日历。

## 学习目标

先修：第2章的缺失值与表格操作，第6章的统计估计，第12章的金融收益，第17章的数据契约、投递账本与版本。

完成后应能：区分数据错误与经济异常；描述缺失机制；推导插补对均值和方差的影响；构造仅使用历史信息的稳健异常分数；设计原值、处理值、质量标记三者分离的数据模型；实现可审计的清洗流水线，并用反例验证它没有制造虚假收益或利用未来信息。

本章不以“清洗后没有空值”为成功标准。目标是让每一次使用、修改、暂缓和拒绝都有清楚依据。

## 18.1 缺失、重复、极值与单位错误的识别

### 18.1.1 数据错误和市场异常是两种判断

**数据质量（Data Quality）**描述数据是否满足明确用途所要求的准确性、完整性、一致性、及时性和可追溯性。数据质量不是单一分数：更及时的数据可能尚未经人工核验，更完整的历史数据也可能包含当时未知的修订。

**异常值（Outlier）**是在某种统计参照下显得不寻常的观测。**错误值（Erroneous Value）**是经证据确认不符合所记录事实或数据契约的值。异常值未必错误，错误值也未必显著异常。

股票下跌8%可能是真实风险事件；价格小数点错一位可能是录入错误；把美元价格误标成人民币，即使数值落在历史常见范围内，也仍是错误。

NIST将异常识别与处理区分开来，并提醒不能在缺少依据时简单删除异常点。本章因此将统计规则用作“待核查标记”，而不是自动删除命令。[NIST异常值检测](https://itl.nist.gov/div898/handbook/eda/section3/eda35h.htm)

采用两层规则：

| 层次 | 判断依据 | 本章动作 |
|---|---|---|
| 硬约束 | 类型、单位、身份、时间、约定值域 | 隔离并保留输入 |
| 软约束 | 相对历史分布是否罕见 | 保留数值并标记 |

“价格为正”是本章四类人工对象的硬契约，不是所有金融工具的通用规律。对可出现负价格的期货，必须另定契约。不能将自然语言中的“通常”写成无例外的数据库约束。

### 18.1.2 先定义观测网格，再说缺失

**观测网格（Observation Grid）**是任务希望观察的资产与时间组合。没有网格，就没有明确的“应该有一条”。

日线任务中的缺失，需要结合交易日历判断；逐笔成交任务中一段时间没有成交，不一定代表丢包。停牌、闭市、无成交、供应商断流和解析失败应使用不同原因码。

设预期资产—时点集合为 $G$ ，有效真实观测集合为 $O$ 。观测覆盖率为：

```math
C_{\mathrm{observed}}=\frac{\lvert O\cap G\rvert}{\lvert G\rvert}.
```

如果另有插补集合 $F$ ，展示覆盖率可以定义为：

```math
C_{\mathrm{display}}=
\frac{\lvert (O\cup F)\cap G\rvert}{\lvert G\rvert}.
```

两者不能混报。插补增加展示可用性，并没有增加真实观测数量。

本章生成器明确提供4资产乘24时点，共96个预期网格位置。真实接入时必须先有日历、序号或发布计划，不能从收到多少条反推应到多少条。

### 18.1.3 缺失机制：MCAR、MAR与MNAR

令完整数据为 $X$ ， $R$ 为缺失指示，约定 $R=1$ 表示观测到。已观测部分记作 $X_{\mathrm{obs}}$ ，未观测部分记作 $X_{\mathrm{mis}}$ 。

**完全随机缺失（Missing Completely At Random，MCAR）**要求缺失机制不依赖数据值：

```math
P(R\mid X_{\mathrm{obs}},X_{\mathrm{mis}})=P(R).
```

例如在理想化实验中，独立随机丢弃固定比例消息。实际网络故障未必满足此条件。

**随机缺失（Missing At Random，MAR）**表示：给定已观测信息后，缺失概率不再依赖未观测部分：

```math
P(R\mid X_{\mathrm{obs}},X_{\mathrm{mis}})
=P(R\mid X_{\mathrm{obs}}).
```

名称中的“随机”容易误解。若某供应商在已知高负载时更易丢包，而且所有相关负载因素都被记录，可能建立MAR模型；它并不要求每条记录的缺失概率相同。

**非随机缺失（Missing Not At Random，MNAR）**表示给定已观测信息后，缺失概率仍依赖未观测值。例如最剧烈的价格变动恰好最容易在尚未观测的高峰中丢失。

MCAR、MAR和MNAR是关于数据生成与观测过程的假设，不是看一张缺失热力图就能确认的标签。尤其不能仅凭已观测数据证明MAR成立。相关定义及完整案例分析的适用边界可参考墨尔本大学统计咨询中心资料。[Missing data](https://scc.ms.unimelb.edu.au/resources/preparing-your-data/missing-data)

### 18.1.4 删除缺失记录为何可能改变分布

设真实变量密度为 $f(x)$ ，观测概率为 $\pi(x)=P(R=1\mid X=x)$ 。由条件概率：

```math
f(x\mid R=1)
=\frac{P(R=1\mid X=x)f(x)}{P(R=1)}
=\frac{\pi(x)f(x)}{\int\pi(u)f(u)\,du}.
```

若 $\pi(x)$ 随 $x$ 变化，观测样本的分布一般不同于原分布。因此完整案例均值所估计的是：

```math
E[X\mid R=1]
=\frac{E[X\pi(X)]}{E[\pi(X)]},
```

而不一定是 $E[X]$ 。

例如真实收益为正负10%，各占一半；上涨时全部收到，下跌时只收到一半。真实均值为零，但观测样本中正收益比例为2/3、负收益比例为1/3，所以观测均值为：

```math
\frac23(0.10)+\frac13(-0.10)=0.03333\ldots.
```

这是缺失选择造成的偏差，不是策略创造了收益。

若在明确模型下知道每个观测被保留的概率，可以考虑**逆概率加权（Inverse Probability Weighting，IPW）**。当 $\pi(X)\gt 0$ 时：

```math
E\left[\frac{RX}{\pi(X)}\middle|X\right]
=\frac{X}{\pi(X)}E[R\mid X]=X.
```

再取期望得到：

```math
E\left[\frac{RX}{\pi(X)}\right]=E[X].
```

推导不意味着真实金融数据总能使用IPW：缺失值本身可能影响未知的 $\pi$ ，小概率还会产生巨大权重；观测概率模型错误会引入新的偏差。本章程序不估计IPW，不把缺失机制视为已知。

### 18.1.5 重复、冲突、修订与陈旧值

沿用第17章的区别：

- 同键同内容：重复投递。
- 同键异内容：冲突，不能随意取最后一条。
- 合法新版本：修订，应保存版本关系。
- 数值长时间不变：可能是真实稳定，也可能是陈旧报价。

**陈旧度（Staleness）**描述信息距离最近真实更新已经经过多久。仅看到价格连续相同不能证明断流，还需心跳、序号、交易状态等证据。

本章输入已经在网格层表达成单值观测，每资产每时点只允许一个业务值，不支持直接混入修订。需要修订时，应先用第17章版本账本构造某一截至时点快照，再将快照送入本章流程。单纯的`drop_duplicates(keep="last")`既没有版本契约，也不能替代这一过程。

### 18.1.6 多证据核验，而不是凭幅度猜测

对可疑价格应检查：单位和币种是否一致；价格类型是否改变；是否发生拆股、分红或换月；同源序号是否连续；其他合法来源是否支持；是否存在正式纠错。

多来源一致也不是绝对真值，因为它们可能共享同一个上游错误。主张“已经修正”应提供证据标识和处理版本；只有统计分数时，应写“待核查”。

## 18.2 插补、稳健变换与隔离重放策略

### 18.2.1 插补是引入假设，不是恢复事实

**插补（Imputation）**是为缺失值构造替代值。替代值应另存，不覆盖原始缺失标记。常见选择包括保留缺失、常数填充、前向填充、插值和模型插补。

保留缺失适合能处理掩码的模型；前向填充适合展示最近已知报价；插值可用于明确的事后重建；模型插补需要训练边界与不确定性表达。不存在对所有金融任务都正确的方法。

pandas提供缺失检测、填充及插值工具，但函数能执行不等于经济假设成立。`ffill(limit=2)`限制的是连续填充位置数量，不自动等同于“最多陈旧两分钟”。不规则时间索引还应检查实际时间差。[pandas缺失数据指南](https://pandas.pydata.org/docs/user_guide/missing_data.html)

### 18.2.2 均值填充为何压低方差

考虑理想条件： $R$ 与 $X$ 独立，观测概率为 $p$ ；真实均值为 $\mu$ ，方差为 $\sigma^2$ 。用已知真实均值填缺失：

```math
Y=RX+(1-R)\mu.
```

减去均值：

```math
Y-\mu=R(X-\mu).
```

因此：

```math
E[Y-\mu]=E[R]E[X-\mu]=0.
```

又因 $R^2=R$ ：

```math
\mathrm{Var}(Y)
=E[R(X-\mu)^2]
=p\sigma^2.
```

若20%缺失，理想均值填充后的总体方差只剩原来的80%。使用估计均值还会引入估计误差；相关缺失时，上述简单比例不再成立。这个推导说明即使均值未偏，风险分布也可能被人为压缩。

多重插补通过多次生成合理缺失值表达不确定性，但它仍依赖插补模型和缺失机制假设。不能把一次确定性填充值视作同等精度的真实观测。

### 18.2.3 前向填充与收益不能混算

**前向填充（Forward Fill）**使用最近一个已知值。记最近真实观测时点为 $s(t)$ ，允许最大年龄为 $L$ ：

```math
\widetilde P_t=
\begin{cases}
P_{s(t)}, & t-s(t)\le L,\\[0pt]
\text{缺失}, & t-s(t)>L\text{或无历史观测}.
\end{cases}
```

必须基于最近真实观测计算年龄，不能每填一次就把年龄归零，否则会无限延长过期数据。

例如真实可见价格序列为100、缺失、110。填成100、100、110后，简单收益变成0和10%。但真实缺失期间可能先跌后涨，也可能逐步上涨；两期路径未知。0只是填充规则的产物。

若只知道端点，能计算两期累计收益：

```math
R_{0,2}=\frac{110}{100}-1=10\%.
```

不能将它伪装成第二期的单期真实收益。本章仅在相邻网格时点都存在合法真实观测时计算单期收益；缺口之后的首个价格恢复点不计算单期收益。

### 18.2.4 线性插值和未来信息

若 $t_0\lt t\lt t_1$ ，线性插值为：

```math
\widetilde x_t
=x_{t_0}+\frac{t-t_0}{t_1-t_0}(x_{t_1}-x_{t_0}).
```

它依赖右端点 $x_{t_1}$ 。即使最终文件中两端都有值，在时点 $t$ 作实时决策时也不能假定未来端点已知。

同理，以当前时点为中心的双侧滚动中位数会用到未来窗口。本章使用**因果窗口（Causal Window）**：当前分数的参照只能来自当前记录之前已经接受的真实收益。

“按时间排序”并不能自动消除泄漏。历史修订、未来插值、全样本标准化和事后数据筛选都可能在排序后继续泄漏。

### 18.2.5 中位数、MAD及其尺度校准

均值容易被单个极端值拉动。中位数只依赖排序位置；在大样本意义下，需要接近一半样本受到任意污染，才能把中位数推到任意远处。这个稳健性不是“任何比例污染都无影响”。

**中位数绝对偏差（Median Absolute Deviation，MAD）**定义为：

```math
m=\mathrm{median}(x_1,\ldots,x_n),
\qquad
\mathrm{MAD}=\mathrm{median}(\lvert x_i-m\rvert).
```

MAD与标准差不是同一个统计量。为何常出现1.4826？

令 $X=\mu+\sigma Z$ ，其中 $Z$ 是标准正态变量。对称性给出总体中位数 $\mu$ 。若绝对偏差的中位数为 $d$ ，则：

```math
P(\lvert X-\mu\rvert\le d)=\frac12.
```

标准化并利用正态分布函数 $\Phi$ ：

```math
P(-d/\sigma\le Z\le d/\sigma)
=2\Phi(d/\sigma)-1=\frac12.
```

因此：

```math
\Phi(d/\sigma)=\frac34,
\qquad
d=\sigma\Phi^{-1}(0.75).
```

由于 $\Phi^{-1}(0.75)\approx0.67448975$ ：

```math
\sigma\approx\frac{\mathrm{MAD}}{0.67448975}
\approx1.4826\,\mathrm{MAD}.
```

这是正态参照下的尺度校准，不能保证厚尾金融收益经校准后服从正态。[NIST MAD说明](https://itl.nist.gov/div898/software/dataplot/refman2/auxillar/mad.htm)

本章用历史收益中位数 $m_t$ 和MAD构造：

```math
s_t=\max\left(\frac{\mathrm{MAD}_t}{0.67448975},s_{\min}\right),
\qquad
z_t=\frac{r_t-m_t}{s_t}.
```

当绝对分数超过3.5时标记。3.5取自常见修改Z分数筛查惯例，不是金融危机概率阈值。尤其在滚动估计、小样本、相关和厚尾条件下，不能用标准正态尾概率直接宣称误报率。

若MAD为零，除法无定义。本实验使用预先固定的正尺度下限，并记录在配置中。下限不是从全样本反推的最优参数。

### 18.2.6 为什么检测收益而不是统一检测价格

同样价格变化1元，对10元股票和2000美元黄金的相对意义不同。本章对每项资产分别计算对数收益：

```math
r_t=\log P_t-\log P_{t-1}.
```

然后与该资产自己的历史收益比较。这样仍不能自动处理拆股、合约换月、陈旧报价和异步交易，但避免了直接混合不同价格尺度。

窗口只收集合法、相邻真实价格产生的收益。当前收益先评分，再加入历史。若当前值先进入窗口，会拉动自己的参照分布，造成**自我掩蔽（Self-Masking）**。

本实验保留被标记的合法收益，并在评分后纳入未来窗口。理由是单凭统计异常不能确认错误；代价是持续污染也会进入窗口。另一方案是冻结或隔离可疑值，但可能让模型永远无法适应新状态。生产上应区分“未确认异常”和“确认错误”，并保留策略版本。

### 18.2.7 缩尾与Huber损失的适用位置

**缩尾（Winsorization）**把超出边界的值压到边界：

```math
T(x)=\min(\max(x,a),b).
```

它与删除观测不同，但都会改变尾部分布。用于模型输入时应另存处理特征，不能回写原始收益，也不能把缩尾后的波动率作为真实市场风险统计。

**Huber损失（Huber Loss）**在小残差处使用平方惩罚，大残差处使用线性惩罚：

```math
\rho_\delta(u)=
\begin{cases}
u^2/2,&\lvert u\rvert\le\delta,\\[0pt]
\delta\lvert u\rvert-\delta^2/2,&\lvert u\rvert>\delta.
\end{cases}
```

取导数：

```math
\psi_\delta(u)=
\begin{cases}
u,&\lvert u\rvert\le\delta,\\[0pt]
\delta\,\mathrm{sign}(u),&\lvert u\rvert>\delta.
\end{cases}
```

大残差的梯度被限制在固定幅度，单点影响不再随残差无限增长；边界两侧损失和一阶导数连续。但这只是改变估计目标，并不证明该点是错误数据。金融尾部风险模型尤其不能因“稳健”就忽略真实危机尾部。

## 18.3 原始数据保留、清洗日志与质量验收

### 18.3.1 三层数据及处理状态

保留三个层次：

1. 原始输入：收到什么、何时收到、来源与原始标识。
2. 清洗结果：采用何种规则、输出何值、为何标记或隔离。
3. 分析特征：根据哪些真实值或处理值、何时计算、模型是否允许使用。

本章状态为：

| 状态 | 语义 | 是否产生输出记录 |
|---|---|---|
| OBSERVED | 通过硬约束的真实输入，未被软规则标记 | 是 |
| FLAGGED | 合法但统计异常，数值保留 | 是 |
| IMPUTED | 缺失位置的有限期展示填充 | 是 |
| MISSING | 无合格填充值 | 是，值仍为空 |
| DUPLICATE | 同键同内容投递 | 否，保留审计 |
| QUARANTINE | 违反硬约束或同键冲突 | 否，保留审计 |

FLAGGED仍属于真实观测。IMPUTED属于生成值。图表应能显示区别，特征服务应能据此决定是否使用。

### 18.3.2 不删除证据的清洗日志

每次投递记录receipt_id、输入摘要、动作和原因；每条结果记录source_receipt、raw_price、view_price、age、status、log_return及score。

生产日志还需增加规则版本、代码版本、原始对象位置、处理开始/结束时间和依赖数据版本。本实验在manifest保存策略版本和哈希，完整输入另存inputs.json。

本程序接收的是已经解析的JSON兼容字典，摘要对应稳定序列化内容，**不等于原始网络字节摘要**。真实接入仍应使用第17章的raw BLOB账本。二者职责不同，不应声称本章替代了原始字节存证。

### 18.3.3 用守恒关系与前缀不变性验收

接收守恒：

```math
N_{\mathrm{receipt}}=
N_{\mathrm{observed}}+N_{\mathrm{flagged}}
+N_{\mathrm{imputed}}+N_{\mathrm{missing}}
+N_{\mathrm{duplicate}}+N_{\mathrm{quarantine}}.
```

输出守恒：

```math
N_{\mathrm{output}}=
N_{\mathrm{observed}}+N_{\mathrm{flagged}}
+N_{\mathrm{imputed}}+N_{\mathrm{missing}}.
```

这能暴露静默丢行或重复输出，但不能证明金融语义正确，还需单位、版本和因果性测试。

**前缀不变性（Prefix Invariance）**要求：在配置固定时，对前 $k$ 条输入的处理结果，与处理完整输入后对应的前缀结果一致。未来追加或改变不应影响过去已经发布的结果。

该性质适用于实时结果；事后修订应发布新的重述版本，不能悄悄改写当时服务过的记录。

### 18.4.2 完整代码

[独立程序](./code/ch18/cleaning_lab.py)和[测试](./code/ch18/test_cleaning_lab.py)已保存。核心程序完整如下：

```python
"""SYNTHETIC causal cleaning lab. Python standard library only."""
import copy
import hashlib
import json
import math
from collections import Counter, deque
from datetime import datetime, timezone
from pathlib import Path
from statistics import median

UNITS = {"EQ_DEMO": "CNY/share", "BOND_DEMO": "percent_of_par_clean",
         "GOLD_DEMO": "USD/troy_ounce", "FX_DEMO": "CNY/USD"}
CONFIG = dict(window=8, minimum=6, threshold=3.5, floor=0.00001, max_age=2)


def encode(x):
    return json.dumps(x, sort_keys=True, ensure_ascii=False, allow_nan=False)


def clean(rows, config=None):
    cfg = dict(CONFIG if config is None else config)
    if not (0 < cfg["minimum"] <= cfg["window"] and cfg["floor"] > 0
            and cfg["threshold"] > 0 and cfg["max_age"] >= 0):
        raise ValueError("Invalid configuration")
    seen, states, outputs, audit = {}, {}, [], []
    for receipt_id, row in enumerate(rows, 1):
        raw = encode(row)  # Teaching input is already decoded JSON.
        digest = hashlib.sha256(raw.encode("utf-8")).hexdigest()
        log = dict(receipt_id=receipt_id, input_sha256=digest)
        def reject(reason):
            audit.append(dict(log, action="QUARANTINE", reason=reason))
        if set(row) != {"asset", "t", "available", "unit", "price"}:
            reject("SCHEMA"); continue
        asset, t, available, price = (row[k] for k in ("asset", "t", "available", "price"))
        if asset not in UNITS or type(t) is not int or type(available) is not int or available < t:
            reject("IDENTITY_OR_TIME"); continue
        key = (asset, t)
        if key in seen:
            if seen[key] == raw:
                audit.append(dict(log, action="DUPLICATE", reason="SAME_CONTENT"))
            else:
                reject("SAME_KEY_CONFLICT")
            continue
        if row["unit"] != UNITS[asset]:
            reject("UNIT"); continue
        if price is not None and (type(price) not in (float, int)
                                  or not math.isfinite(price) or price <= 0):
            reject("PRICE"); continue
        state = states.setdefault(asset, dict(t=-1, available=-1, last=None,
                                              history=deque(maxlen=cfg["window"])))
        if t <= state["t"] or available < state["available"]:
            reject("ORDER_REQUIRES_REPLAY"); continue
        seen[key] = raw
        last = state["last"]
        age = None if last is None else t-last[0]
        ret = score = None
        if price is None:
            view = last[1] if last and age <= cfg["max_age"] else None
            status = "IMPUTED" if view is not None else "MISSING"
            reason = "BOUNDED_FORWARD_FILL" if view is not None else "NO_FRESH_ANCHOR"
        else:
            view, status, reason = price, "OBSERVED", "VALID_DOMAIN"
            # A missing or quarantined grid point breaks the one-step return.
            if last and last[0] == t-1:
                ret = math.log(price)-math.log(last[1])
                history = state["history"]
                if len(history) >= cfg["minimum"]:
                    center = median(history)
                    mad = median(abs(x-center) for x in history)
                    scale = max(mad/0.6744897501960817, cfg["floor"])
                    score = (ret-center)/scale
                    if abs(score) > cfg["threshold"]:
                        status, reason = "FLAGGED", "ROBUST_RETURN_SCORE"
                else:
                    reason = "WARMUP"
                history.append(ret)  # Score first; update afterwards, including flagged values.
            state["last"] = (t, price)
            age = 0
        outputs.append(dict(asset=asset, t=t, available=available, raw_price=price,
                            view_price=view, age=age, status=status, log_return=ret,
                            score=score, source_receipt=receipt_id))
        audit.append(dict(log, action=status, reason=reason))
        state["t"], state["available"] = t, available
    return dict(config=cfg, output=outputs, audit=audit,
                counts=dict(Counter(x["action"] for x in audit)))


def samples():
    rows = []
    for asset, initial in zip(UNITS, (100.0, 99.0, 2000.0, 7.0)):
        price = initial
        for t in range(24):
            price *= math.exp((0.001, -0.001, 0.0005, -0.0005)[t % 4])
            if asset == "EQ_DEMO" and t == 16:
                price *= 0.92  # Genuine synthetic market jump, retained.
            value = None if asset == "EQ_DEMO" and t in (9, 10, 11) else price
            row = dict(asset=asset, t=t, available=t, unit=UNITS[asset], price=value)
            if asset == "BOND_DEMO" and t == 12:
                row["unit"] = "CNY"
            if asset == "GOLD_DEMO" and t == 12:
                row["price"] = -1
            rows.append(row)
    rows.sort(key=lambda r: (r["available"], r["asset"]))
    rows.insert(5, copy.deepcopy(rows[4]))
    conflict = copy.deepcopy(rows[0]); conflict["price"] *= 1.1
    rows.append(conflict)
    return rows


def main():
    root = Path(__file__).parent
    out = root/"runs"/datetime.now(timezone.utc).strftime("run_%Y%m%dT%H%M%S_%fZ")
    out.mkdir(parents=True)
    rows = samples()
    result = clean(rows)
    (out/"inputs.json").write_text(encode(rows)+"\n", encoding="utf-8")
    (out/"results.json").write_text(encode(result)+"\n", encoding="utf-8")
    manifest = dict(data_kind="SYNTHETIC", policy_version="ch18-v1",
                    time_unit="abstract grid step; zero processing delay assumed",
                    hashes={p.name: hashlib.sha256(p.read_bytes()).hexdigest()
                            for p in (Path(__file__), out/"inputs.json", out/"results.json")})
    (out/"manifest.json").write_text(encode(manifest)+"\n", encoding="utf-8")
    print(result["counts"])
    print("output rows:", len(result["output"]), "receipts:", len(rows))
    print(out.resolve())


if __name__ == "__main__":
    main()
```

### 18.4.4 代码机制与工程边界

每条输入先生成摘要和投递日志标识，再检查硬约束。重复不会更新状态；冲突不覆盖已接受值。每项资产的last只记录最近真实合法价格；前向填充不更新last，因而不会不断刷新陈旧年龄。

ret仅在last时点恰为当前前一网格点时产生。历史窗口存储的是最近若干合格收益，不保证覆盖固定长度的日历区间；若需要固定时间窗口，应额外记录每个收益的时间并按年龄淘汰，第19章将讨论这一差别。

软异常先评分后入窗；被标记值仍更新真实价格锚点。每次输出可以通过source_receipt追溯原输入。

程序将整批结果写入新目录；没有承诺逐条崩溃恢复。异常返回的audit是内存处理结果，最终保存前崩溃不能依赖它恢复。需要持久实时处理时，应与第17章事务账本集成，不能把“有JSON文件”宣传为完整恢复机制。

本章用浮点处理模拟分析价格，不替代第17章定点数的精确金额账本。复杂报价、宏观修订和文本清洗应采用各自类型规则，不能套用一个收益阈值。

### 18.4.5 测试与性能

10项测试验证：计数守恒；输入未修改；填充年龄与收益断点；真实跳跌保留；前缀及未来扰动不变；重复不改状态；硬错误之后不造收益；MAD为零时分数有限；乱序不被静默重排；全缺失保持缺失。

中位数排序实现每条评分约需 $O(w\log w)$ ，其中 $w$ 为窗口长度。资产状态约需 $O(Aw)$ 空间；本实验还缓存全部输出和审计，因此总内存另有 $O(N)$ 。不能只报告窗口状态空间而忽略日志。

大规模运行可增量写审计、分区处理，并用支持删除的顺序统计结构优化窗口。近似分位数可降低代价，但必须评估误差对报警边界的影响。性能优化不能先取消原始证据和原因码。

## 本章总结

清洗是带假设的转换，不是把数据变得平滑。先核对身份、单位、时间和版本，再用统计规则识别可疑变化；硬错误隔离，真实极端值保留证据。

缺失机制影响可识别性和估计偏差。均值填充可能压低方差，前向填充可能制造零收益，双侧插值可能使用未来信息。MAD提供稳健尺度参照，但阈值不是危机概率。

工程验收既要看结果数值，也要看投递守恒、来源追踪、前缀不变性和失败行为。本章完成了可运行的因果清洗实验，下一章进入真实交易日历、时区和多频率对齐。

## 详细参考答案

### 1. 异常与错误

异常是相对参照分布的判断，错误是相对事实或契约的判断。真实政策冲击导致跳跌应保留；把报价单位由CNY/USD误写为USD/CNY，即使价格数值常见，也应隔离。仅有极端幅度没有提供纠错证据。

### 2. 缺失机制

独立于所有数据值的随机丢包可对应MCAR；若给定已记录负载后，丢包与未观测数据无关，可对应MAR；若仍依赖未观测跌幅，则对应MNAR。现实机制可能同时包含多种因素，所以不能仅凭原因名称确认条件独立假设。

### 3. 观测均值

正、负且被观测到的联合概率分别为1/2和1/4；总观测概率3/4。条件概率分别为2/3、1/3，观测均值为1/30，约3.333%。更多样本只会使样本均值更接近这个偏移后的目标，不会自动回到真实均值零。

### 4. 标准差比例

由已推导结果，方差变为0.7倍。标准差是方差平方根，因此：

```math
\frac{\sigma_Y}{\sigma_X}=\sqrt{0.7}\approx0.83666.
```

即下降约16.33%，不是下降30%。若缺失依赖收益，不能继续直接套用该比例。

### 5. 有限前向填充

展示序列为100、100、100、缺失、104；年龄为0、1、2、3、0。四个可能的相邻收益均没有两端相邻真实观测，因此本规则不计算任何单期收益。

端点累计收益可单独记为104/100−1=4%，持有期为4步。不能把4%写成最后一步收益，也不能把前两步的填充变化视为真实零收益。

### 6. MAD计算

中位数是2，绝对偏差为2、1、0、1、98，排序后中位数为1。因此校准尺度约1.4826，100的分数为：

```math
z=\frac{100-2}{1/0.67448975}
=98\times0.67448975\approx66.1000.
```

这是明显的统计标记，但“100是什么”仍需业务背景：它可能是单位错位，也可能来自真实结构改变。该例用同一批数据演示公式；在线实验不能用包含当前及未来值的整批参照。

### 7. Huber边界

内部导数为 $u$ 。正侧外部导数为 $\delta$ ，负侧为 $-\delta$ ，故在 $u=\delta$ 和 $u=-\delta$ 处都与内部导数一致。

正边界损失两侧均为 $\delta^2/2$ ，负边界同样如此，所以损失和一阶导数连续。二阶导数则从内部1变成外部0，边界处一般不能用单一二阶导数描述。平方损失梯度随残差无限增大，Huber将大残差梯度幅度限制为 $\delta$ 。

### 8. 泄漏判断

中心窗口与后向填充通常使用未来观测；全样本分位数若包含验证或测试期，也泄漏。只用已可用历史窗口计算MAD可以满足因果性，但还需确保窗口成员没有未来修订、参数没有用测试期挑选。

若任务明确是事后重建，双侧插值可作为该任务的方法，但其结果不能再被标成实时在线结果。若分位数只在训练期拟合并冻结，则不属于全样本泄漏。

### 10. 三种比例

真实观测91/96约94.79%；展示非空93/96为96.875%；输出记录94/96约97.92%。

输出94行包含90条OBSERVED、1条FLAGGED、2条IMPUTED、1条MISSING。2条硬错误对应的网格位置没有标准输出，额外冲突和重复不增加网格位置。不能把NULL输出行或插补行计作真实行情。

### 11. 风险统计影响

把尾部压到±5%会让面板中的极端冲击变小，改变超过该边界的损失分位数及尾部均值，也通常压低围绕零计算的平方收益总量。一般样本方差还受中心变化影响，不应不加条件宣称任何缩尾都按固定比例降低方差。

更合理的分层是：保存原始值及确认纠错版本；给合法极端值添加标记；必要时为某个模型另建缩尾特征，并记录训练边界和阈值。风险报告应明确使用哪一层，不能拿模型输入的压缩尾部当市场真实风险。

### 12. 修复与重放

参考流程：隔离错误记录；核对供应商正式说明或可信主数据；确认究竟是标签错、数值错还是报价方向变化；形成有证据链接的修复版本，记录原值、新值、单位、规则版本和实际修复时间；在隔离输出目录重放受影响区间；比较修复前后价格、收益、状态和报警，再发布新版。

不能因为“乘100看起来像正常价格”就自动修复。缺少证据时保留待核查。

历史在线记录保持原样；事后重述结果带新的版本和可用时间。恢复失败时保留原始输入及失败原因，重试应幂等，不重复产生同一修复版本。

评价标准：原始证据完整；变更理由可核实；依赖范围可定位；重复重放结果一致；未来修复不回填成历史实时信息；质量指标分母明确；模型和面板能追溯到具体版本。仅“图变平滑”不算验收通过。
