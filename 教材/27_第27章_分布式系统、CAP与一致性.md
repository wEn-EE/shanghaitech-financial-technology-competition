# 第27章 分布式系统、CAP与一致性

股票 EQ_DEMO 的初始报价是 100.10 元。接入节点已确认新价 97.10，交易室的看板却仍显示 100.10，右上角写着“12 毫秒前更新”。两个价格都能在日志里找到。要判定系统是否出错，还缺一项信息：这个查询接口究竟承诺读到什么？

**学习目标。** 先修第 20 章的数据可用时间、第 25 章的重放和第 26 章的收据。读完本章，应能从调用与返回记录判断一次读是否违反线性一致性，复述网络分区下的不可区分性证明，为看板、特征服务和预警配置分别制定读写契约，并用同一条报价复现实验中的反例。

## 27.1 节点、网络分区、时钟与故障模型

**节点（node）**是独立执行和收发消息的参与者。**副本（replica）**保存同一逻辑对象的一个拷贝。接入节点 A 和查询节点 C 各有一份最新报价时，A 改动自己的内存，只有消息传到 C 且被应用，C 的本地读者才会看到变化。跨节点传播给第 26 章的“已提交”和“下游可见”之间又添了一段时间。

**部分故障（partial failure）**指一部分组件失效时其余组件仍能运行。进程崩溃停止（crash-stop）时，它此后停止执行；崩溃恢复（crash-recovery）允许进程重启，内存状态消失，重启后根据持久日志恢复。网络分区（network partition）则允许双方继续计算，但跨越某些节点集合的消息无法送达。单向断链也能破坏一次请求加回执所需的往返路径。实验将 A、B 放在一侧，C 放在另一侧，保留 C 的本地读能力。

**故障模型（failure model）**规定证明或实现需要处理哪些执行。同步模型给通信和处理规定已知时间上界；异步模型允许消息和调度等待任意长时间。等了 100 毫秒可以触发切换流程；在异步模型中，仅凭这段沉默，慢节点、丢了回执的节点和已经停机的节点具有相同的外部表现。部分同步模型允许系统经过一段不确定时期后满足时限，选主协议可以利用随后稳定的通信取得进展。

### 从墙上时间到因果顺序

物理时钟能标记开市时间和数据发布时间。若 A 的钟快 8 毫秒、C 的钟慢 8 毫秒，一条在真实时刻 100 毫秒发送、106 毫秒到达的消息，日志会写成“108 发送、98 接收”。设各时钟相对真实时间的绝对误差上界为 $\epsilon$ ，观测的跨机耗时为 $d$ 。发送和接收的误差分别为 $e_s,e_r$ ，真实耗时为 $D$ ，则

```math
d=(t_r+e_r)-(t_s+e_s)=D+e_r-e_s.
```

两项误差各能取到正负界，故真实耗时落在 $[d-2\epsilon,d+2\epsilon]$ ，再与非负区间取交集。本例观测为 −10 毫秒，若误差上界为 8 毫秒，真实耗时的可能范围是 0 到 6 毫秒。单机测一段耗时用单调时钟；跨机器比较必须交代同步误差。

**先发生关系（happened-before）**由三条规则生成：同一执行流内的先后顺序、同一消息的发送先于接收，以及这两条关系的传递闭包。任意方向都没有先发生路径的两个事件称为并发事件。Lamport 逻辑时钟让节点在本地事件前把计数加一，收到时间戳 $s$ 的消息时，用本地原值 $c$ 计算更新值：

```math
c_{\mathrm{new}}=\max(c,s)+1.
```

沿一条本地边，计数严格增大；沿一条消息边，接收值严格大于发送值；沿多条边反复应用这个结论即可比较因果链两端。反推会出错：互不通信的两台机器独立做两步和三步计算，也会出现 2 小于 3。即使再用节点编号打破同值以便排序，得到的仍是人为选定的全序；独立发布的股票新闻和债券新闻之间没有因此增加一条因果边。[Lamport，1978](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/12/Time-Clocks-and-the-Ordering-of-Events-in-a-Distributed-System.pdf)

## 27.2 一致性模型、复制、共识与CAP边界

### 一条读记录怎样构成反例

把“最新股票报价”抽象为一个**寄存器（register）**。顺序执行时，写操作替换值，读操作返回最近一次写入的值。并发历史为每次操作保留调用和返回两个端点。**线性一致性（linearizability）**要求能在每个成功操作的两个端点间选一个生效点，使排出的顺序符合寄存器规则。甲已经返回、乙才调用时，甲必须排在乙之前。[Herlihy 与 Wing，1990，§2](https://cs.brown.edu/`mph/HerlihyW90/p463-herlihy.pdf)

初值 100.10，写 97.10 在时刻 8 调用、10 返回。读在 9 调用、11 返回，两者重叠，读旧值可以把读排在写之前，读新值可以把读排在写之后。改为读在 12 调用、13 返回，而且中间没有其它写：此时返回 100.10 就是一个完整反例。验证一段记录时，把真实时间强制的先后画成箭头，然后尝试排列重叠操作。只有调用时间、缺少返回时间的日志，会丢掉判断所需的边界。

| 读写承诺 | 使用者能依赖的性质 | 行情例子 |
|---|---|---|
| 顺序一致性（sequential consistency） | 存在遵守各客户端自身操作次序的合法总序 | 不同客户端之间还可能缺少真实时间约束 |
| 因果一致性（causal consistency） | 有依赖关系的写按因果顺序可见 | 若先读到公告再写解读，读者看到解读时应能取得相应公告 |
| 单调读（monotonic reads） | 同一会话成功读到的版本不倒退 | 从 B 切到 C 时，请求携带已见版本 2 |
| 最终一致性（eventual consistency） | 更新停止，且复制与修复持续取得进展后，各副本收敛 | 分区修复后补齐日志；收敛时间需另行测量 |

“读己之写”（read-your-writes）让同一会话后续读取至少包含自己的成功写入。一个交易员只读不写，切换副本时仍可能关心单调读。单对象读满足线性一致性，也要分别考虑多对象组合：先读股价，再读债价，两次调用之间可以发生新的发布。需要同一时点的股债状态时，应使用一致快照或携带每个输入版本的快照清单。

### CAP 的两段执行

CAP 中的 C 取原子一致性，对应上述寄存器的线性一致性；A 要求每个发给未故障节点的请求最终得到契约规定的响应；P 描述通信分区可以持续存在。对“读取寄存器”的操作，返回一个错误码能结束 HTTP 调用，调用者仍未获得所请求的值。[Gilbert 与 Lynch，2002，定义及定理 1](https://www.comp.nus.edu.sg/`gilbert/pubs/BrewersConjecture-SigAct.pdf)

设 A 和 C 都活着，两侧消息都无法通过。只研究一个寄存器就足够了。

1. 执行甲中无人写入。读者在 C 请求报价。若要求可用，C 最终须回答；唯一合法值是 100.10。
2. 执行乙中 A 先收到写 97.10 的请求。若写一直等对岸确认，就已经出现一个无法完成的请求。为了同时满足可用性，假定这次写成功返回。
3. 写返回后，另一读者才在 C 调用相同的读。安排 C 的输入、本地执行和收到的消息与甲相同。更新消息滞留在分区另一侧，C 用来作答的证据完全相同。
4. C 若按甲回答 100.10，乙中写已结束，违反线性一致性。若答 97.10，甲中这个值从未写过。若一直等待区分两次执行的消息，持续分区会破坏可用性。

矛盾来自三项条件同时成立：允许这种分区，所有未故障节点上的请求都必须完成，读写还必须服从真实时间顺序。设计接口时应具体写明哪一类操作会等待、拒绝或降级。日常报表里“过去一个月 99.9% 的查询在 200 毫秒内成功”是按时限统计的运行指标，与定理中对所有允许执行的最终响应量词各有用途。

### 从相交副本到复制日志

**法定人数（quorum）**是协议完成某一步所需的一组副本。固定成员数为 $N$ ，写满 $W$ 个节点才确认，读访问 $R$ 个节点。把本次写集合和读集合放到一起，两者的并集最多有 $N$ 个节点。由容斥可得交集大小至少为

```math
|Q_w\cap Q_r|=W+R-|Q_w\cup Q_r|\ge W+R-N.
```

当 $W+R\gt N$ ，至少能找到一个公共节点。五个节点中写三读三，最少重合一个；写三读二，读集合有可能恰好落在没有参加写入的两个节点上。要让任意两个写集合也相交，相同推导给出 $2W\gt N$ 。共有 $2f+1$ 个节点时，多数为 $f+1$ ；失去 $f$ 个后仍剩 $f+1$ 个可参与多数决策，前提是它们能相互通信。

相交只说明“见过某次写的节点可能提供证据”，还得定义**哪些版本已经提交**。举例：三副本初值 0，一次写 1 只到 A 就停住。读者在 A、B 中取最大版本，返回 1；随后另一读者从 B、C 返回 0。两次读取均接触了多数，但一次悬而未决的写无法解释这段先新后旧的顺序。协议可以安排读回写阶段把所见值传播到多数，或从经过确认的提交日志读取。

**共识（consensus）**要让参与者对决定值达成一致，并约束可决定的值及取得进展的条件。复制状态机（replicated state machine）把多次决定排成日志，所有副本用相同的顺序执行确定性命令。若命令是“立即取本机时间设为发布时间”，即使日志相同，输出也可能不同。可在命令中直接写入选定的发布时间。

以 Raft 为例，任期号区分选举轮次；候选者取得多数票且受日志新旧条件约束；领导者复制条目时检查前一条的位置与任期。领导者按当前任期条目在多数副本上的复制情况推进提交位置，较早条目随已提交前缀一起确定。恢复的旧领导者若接触到更高任期必须退位。强读还需确认领导权并等待相应提交位置已应用，否则失去多数联系的旧领导者可能继续答旧值。实验固定单一写者，便于独立考察读取规则；自动选举、磁盘日志和任期切换可结合论文图 2、第 5 节和第 8 节研读。[Ongaro 与 Ousterhout，2014](https://raft.github.io/raft.pdf)

## 27.3 金融监控中的可用性和陈旧数据取舍

看板里的“最新”至少涉及三个量。**事件年龄**等于查询时刻减报价事件时刻，在同一时标上量度行情距今多久。**复制落后量**等于已知已提交头部位置减节点已应用位置，单位是日志条数。**会话下界**来自读者自己已经见过的版本。隔离节点可以知道本地版本和客户端给它的下界；若无法联系权威端，当前全局头部应标为未知。即使落后量为零，休市期间事件年龄仍会自然增大。

| 使用方 | 请求与响应契约 | 出现分区时 |
|---|---|---|
| 人工观察看板 | 返回本地最后报价，同时给出事件时间、版本、取数节点和链路状态 | 保留旧图，停止更新“最新已确认”的标识 |
| 滚动特征服务 | 上游指定最低版本和最大允许年龄，任一条件失败即返回原因 | 保存缺失掩码，禁止把未更新资产的收益自动写成零 |
| 预警规则发布 | 规则版本须从权威写入路径提交，读取者记录实际使用的版本 | 无法确认新配置时保留最近已批准版本及生效范围，界面提示发布待确认 |

按事件年龄设阈值仍要匹配交易时段、资产和用途。教学例中，一次仅有 12 毫秒年龄的报价已落后一个版本；另一个没有任何新写入的市场也可能具有同样的年龄。在一个假设阈值“股价低于 98 元触发人工复核”的演示规则中，100.10 与 97.10 会把判断分到两侧。若风险服务承诺使用至少版本 2，隔离期间应返回数据待齐，保存上次判断的时间与依据。把数据待齐编码成“阈值未触发”会隐藏覆盖缺口。

### 本章总结

看到看板上的一个价格，可以沿三条记录查回去：源发布的是哪个事件，权威端已经提交到哪里，这个读者实际从哪个节点看到了哪一版。CAP 的证明解释了隔离节点缺少哪一份信息；法定人数和复制日志解释了系统怎样取得共同证据；会话版本与年龄字段把业务允许接受的输入写进查询契约。

### 分层练习与详细参考答案

**1．基础。** 两节点都能响应各自机房的健康检查，但跨机房的写入回执丢失。能从检查结果推断写入结局吗？

答：健康检查走的是机房内路径。数据可能还没到写者，也可能已经提交，仅有回执丢失。用同一请求标识向权威端查询或重试，再核对持久结果。告警中要分别记录本地存活、跨机房往返和提交进度。

**2．时钟。** 发送时间戳为 100，接收为 104 毫秒，两台机器各自的误差至多 3 毫秒。求真实耗时范围。再设接收节点逻辑钟为 7，消息逻辑时间戳为 11，求接收事件的新计数。

答：观测差 4，两个误差之差可达正负 6，得区间 [−2,10]；消息先发后收，取交集为 [0,10] 毫秒。逻辑计数取 7 和 11 的较大值再加一，得 12。两次计算分别度量时间长度与事件次序。

**3．历史判读。** 初值 0。写 1 从 2 到 8，读甲从 3 到 4 返回 1，读乙从 5 到 6 返回 0。写操作和两次读均重叠，这段历史能否线性化？

答：甲读到 1，写的生效点必须排在甲之前。甲在乙调用前已经返回，所以又必须排在乙之前。传递得到“写、甲、乙”，其间无其它写，乙应为 1。只逐个检查每次读与写是否重叠，会漏掉两次读之间的强制顺序。

**4．法定人数。** 七节点要求容忍任意两个节点停机，同时读写集合相交。写取 5 时，最少读几个？若目标改成容忍任意三个停机，原方案还能写吗？

答：读集合要大于 7 − 5 = 2，取 3 即可。两个停机后剩 5 个，满足写 5 和读 3 的人数要求，还须这些节点可达。三个停机后只剩 4 个，写 5 无法完成。取写 4、读 4 可满足新的交集与人数条件，版本、提交与读协议仍需另行定义。

**5．编程。** 在 12 毫秒让同一节点按三种策略各读一次，最低版本设为 1，年龄上限设为 20。给出三个返回值，再将最低版本升到 2。

答：在短例的有写分支中，对 `local`、`strict`、`guarded` 分别调用 `cluster.read("C", policy, 12, min_version=1, max_age=20)`。依次得到 OK/v1、UNAVAILABLE、OK/v1；年龄 12 满足门槛。最低版本改成 2 后，前两项不变，第三项变为 BEHIND_SESSION。由此可见单调读下界能保护已经见过 v2 的会话；首次访问的读者需要其它途径确认最新版本。

**6．金融分析。** 两项资产的日内收益原为 0，随后股票跌 3%，债券涨 1%。股票节点停留在旧版本，债券节点已更新。等权组合看板显示多少？共同新快照应是多少？

答：看板若把旧股价沿用为当期价，股收益记 0%，组合为 0.5 × 0% + 0.5 × 1% = +0.5%。以相同前期价格为基准、两项新报价都可见时，组合为 0.5 × (−3%) + 0.5 × 1% = −1%。这 1.5 个百分点的差异来自输入时点。回放时保存两项资产的依赖版本和决策时可见的快照，后来的修复另存一个结果版本。

**7．故障推演。** 执行到 31 毫秒后停机，持久进度应是多少？若只持久化“见过的最大编号”会怎样？

答：C 只应用到 1，31 毫秒到达的 v3 遇到缺口，连续完成位置仍为 1。恢复请求应从 2 开始。若记录最大编号 3，恢复从 4 开始，2 和 3 的处理都可能永久遗漏。让业务结果和连续位置在同一事务内提交，可用“提交前后分别终止、重放、逐键对账”来验证。

**8．开放设计。** 给跨资产看板与预警配置发布设计分区演练，各列出一次可以接受的降级和一次必须阻止的错误。

答：看板允许返回最后可见组合，附每资产事件时刻、版本和缺失掩码；若合约要求共同快照，缺一项就保留上一完整组合。配置发布采用具有任期隔离和持久多数提交的存储，少数侧可查看旧配置及其证据，发布接口返回未确认。用两个读者分别访问两侧并保留请求及返回，网络恢复后比较发布日志、客户端实际应用版本和报警记录。评分各占四分之一：故障时序可重放，接口有可核对的成功条件，旧数据与未确认发布对使用者可见，恢复后的业务输出逐条可追溯。
