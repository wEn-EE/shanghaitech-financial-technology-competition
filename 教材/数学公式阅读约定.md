# 数学公式阅读与排版约定

本教材使用Markdown与数学公式混排，目标是兼容VS Code内置预览和GitHub文件预览。2026-10-23用户补充截图后，确认仅检查数学引擎语法还不够：GitHub的Markdown解析可能先改变公式源码。以下为当前生效约定。

## 1. 普通行内公式

使用单美元符号，公式与相邻中文之间留空格；美元符号内侧不额外留空格，不在行内公式中换行。

```markdown
资产价格为 $P_t$ ，简单收益率为 $r_t$ 。
条件为 $0\lt x\lt1$ ，重抽样值记作 $X^{\ast(b)}$ 。
随机积分记作 $\int_0^T W_t\thinspace dW_t$ 。
```

行内公式使用名称命令来避免与Markdown标点语法相撞：大小于号用 `\lt`、`\gt`，星号用 `\ast`，薄间距用 `\thinspace`。例如 `\,` 在本仓库GitHub页面返回的公式源码中曾变成普通逗号；名称命令可避免这个转义步骤。数学含义保持一致。

矩阵、有多行环境的表达式和含转义百分号的较复杂公式放到独立公式块；不要把一个矩阵硬塞进句子。练习题中的公式块与后续文字须缩进到当前列表项内部，保留题号结构。

## 2. 独立公式统一使用math公式块

GitHub官方支持带math标记的围栏公式块，VS Code当前内置数学扩展也启用了这种写法。它在显示时仍是数学排版，不是等宽源代码。围栏内部不再加美元符号。

下面用四个反引号包围整个示例，避免内部的三个反引号提前结束说明：

````markdown
训练转移计数为：

```math
N=\begin{pmatrix}
821&27\\
26&125
\end{pmatrix},\qquad \sum_{i,j}N_{ij}=999.
```
````

紧凑的同一行矩阵源文在math公式块中也可保留两个反斜杠。较大矩阵仍建议按行写源码，便于人工复核。

旧的双美元公式块是合法数学语法，但本仓库GitHub实际页面曾把其中的行分隔符、间距转义和百分号转义改变；全书改用math公式块保护源码，不通过无差别增加反斜杠修补。

## 3. 名称、括号与多行推导

此前用户实测GitHub拒绝operatorname命令。已审核的span、rank、Var、Cov等普通名称继续用 `\mathrm`；这不是对所有算子的通用等价替换，带上下限或特殊间距的算子需另行核对。

集合边界用 `\lbrace`、`\rbrace`，范数用 `\Vert`；行内绝对值若需定界命令，用 `\lvert`、`\rvert`。表格内避免使用会与分列符冲突的裸竖线。

多行推导使用aligned环境，矩阵使用pmatrix等适当环境；矩阵列用&，行用两个反斜杠。数学分组花括号不得随意改成显示集合的花括号。

````markdown
```math
\begin{aligned}
r_t &= \frac{P_t-P_{t-1}}{P_{t-1}} \\
    &= \frac{P_t}{P_{t-1}}-1.
\end{aligned}
```
````

## 4. 分层验证

1. 数学源文：检查分隔符、完整公式和对应推导。
2. VS Code引擎：使用现有内置KaTeX检查语法；当前内置数学插件已启用math围栏支持。
3. GitHub Markdown：检查官方接口或实际文件页的math-renderer节点，对比识别数量和完整内容，确认反斜杠、星号、百分号没有被改动。
4. 视觉检查：在实际预览页面观察行列数、对齐和上下标；前三项不能代替最终页面布局检查。

`tools/format_math.py` 规范已审核记法，保护普通程序代码，并将独立公式转换为math公式块；默认报告，--write才修改文件。`tools/test_format_math.py` 针对矩阵行分隔、行内识别、代码保护和列表缩进提供回归检查。

`tools/check_github_math.py` 可通过GitHub官方Markdown接口比较公式内容。它会发送明确指定的整个Markdown文件，因此应仅用于用户已授权向该接口提交的内容，不应随意发送私人未公开文稿。此次全文接口检查受自动审批拦截，改为按既有仓库发布授权推送，再只读检查实际GitHub文件页。

`tools/markdown_math.py` 是历史纯文本迁移工具，保留审计用途，不用于改写当前正文。旧的纯文本与双美元约定可在Git历史查看。

## 5. 官方资料与实测边界

- [GitHub：Writing mathematical expressions](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/writing-mathematical-expressions)：行内分隔符、受保护行内语法及math围栏公式块；平台使用MathJax。
- [VS Code：Markdown](https://code.visualstudio.com/docs/languages/markdown#_math-formula-rendering)：内置数学预览及KaTeX；当前安装扩展只读核对到enableFencedBlocks为true，没有修改编辑器文件或配置。
- [KaTeX：Supported Functions](https://katex.org/docs/supported.html)：名称命令、矩阵和对齐环境；支持列表不能代替平台实际解析结果。

此前测试页中的多行矩阵曾通过用户视觉验证；这不意味着同一矩阵紧凑写在一行，或放入句子时会经过相同解析路径。教材的数学含义与程序逻辑不因此次排版调整而改变。
