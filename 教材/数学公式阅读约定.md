# 数学公式阅读与排版约定

本教材采用 Markdown 正文与数学公式混排，目标是同时在 VS Code 内置预览和 GitHub 文件预览中清晰显示。用户已于 2026-10-23 确认修正版公式测试页在 GitHub 正常；原测试页此前在 VS Code 正常。普通不带数学支持的 Markdown 阅读器可能显示公式源码。

## 行内公式

使用单美元符号，公式与前后文字之间留空格；美元符号内侧不额外留空格，不在行内公式中换行。

```markdown
资产价格为 $P_t$ ，简单收益率记作 $r_t$ 。
```

用户实测中，紧贴中文的写法未被 GitHub 识别；因此全书统一保留公式外侧空格。

## 独立公式

使用双美元符号，起止符分别独占一行，公式块前后各留空行。不把正式公式放在普通代码块中。

```markdown
样本标准差为：

$$
s = \sqrt{\frac{1}{n-1}\sum_{i=1}^{n}(r_i-\bar{r})^2}
$$

其中，n 是样本数。
```

本说明中的代码块用于展示 Markdown 源码，不用于模拟实际公式预览；聊天中展示源码时也使用 markdown 代码块，避免 latex 代码块被另外解释。

## 运算名称、集合括号与范数

GitHub 实测拒绝 operatorname 命令。对于本书已核对的 span、rank、Var、Cov 等普通名称，使用直立字形命令；它与算子命令的间距、上下限行为不完全相同，新增算子须单独检查。

```markdown
$$
\mathrm{span}(v_1,\ldots,v_k) = \left\lbrace \sum_{i=1}^{k} c_i v_i : c_i \in \mathbb{R} \right\rbrace
$$

$$
\mathrm{rank}(M) + \dim \mathcal{N}(M) = n
$$
```

集合括号使用 `\lbrace`、`\rbrace`，需要自动调整大小时加 `\left`、`\right`。用户截图表明，原来 `\left\{` 的反斜杠在报错展示中丢失；命名括号的修订已通过用户 GitHub 验证。

范数用 `\Vert x\Vert_2`，避免依赖 `\|` 的反斜杠传递。绝对值与范数不可混淆。表格中的数学表达式应尽量用 `\vert` 或 `\Vert` 表示竖线，避免与表格分列符冲突。

## 多行推导与矩阵

多步等式使用 aligned 环境；不要把单独的等号写成一行，以免未识别的数学块被 Markdown 当成标题。

```markdown
$$
\begin{aligned}
r_t &= \frac{P_t-P_{t-1}}{P_{t-1}} \\
    &= \frac{P_t}{P_{t-1}}-1.
\end{aligned}
$$

$$
M = \begin{pmatrix}
1 & 2 \\
3 & 4
\end{pmatrix}
$$
```

矩阵列之间用 &，行之间用两个反斜杠。下标和上标中有多个字符时使用花括号，例如 `P_{t-1}`。数学分组花括号和用于显示集合边界的命名花括号用途不同，不可全局替换所有花括号。

1. 在 VS Code 中打开 Markdown 内置预览，确认数学渲染设置启用；GitHub 查看文件的 Preview 页面，而不是 Raw 页面。
2. [公式渲染测试页](./公式渲染测试.md)保留六类代表公式及用户验证记录。平台支持列表不能代替具体页面的实际验证。
3. 第1—6章从历史数学源文恢复，保留792个独立公式和1096个行内公式；原有文字、代码和引用保留，仅调整排版所需的空格与数学记法。
4. `tools/format_math.py` 对已核对的命令进行规范化，保留原有代码块；默认只报告，传入 --write 才写入。它不保证所有未来新增公式在所有平台中可用。
5. `tools/markdown_math.py` 是此前纯文本迁移工具，保留以便审计；不要再用它改写当前章节。纯文本排版已被本次数学排版约定替代，旧版本可在 Git 历史查询。
6. 本次1888处公式使用本机 VS Code 所带 KaTeX 0.16.10 检查，全部通过语法渲染；这不等于已在 GitHub 上逐式视觉验收，也不等于重新证明数学结论。未安装解释器或依赖。
