## 19.1 交易时段、节假日、夏令时与跨市场日历

### 19.1.1 一个日期不是一个时刻

**时刻（Instant）**表示时间轴上的一个点。**本地钟表时间（Local Wall Time）**表示某地钟表显示的日期和时间。**时区（Time Zone）**是一组将本地时间映射到时间轴的规则，而不只是一个固定偏移。

例如北京时间2026-10-29 09:30与UTC同日01:30表示同一时刻。只写“09:30”则缺少日期、时区等必要信息。

**协调世界时（Coordinated Universal Time，UTC）**用于本章内部排序和比较。保留原始本地时间、时区名称及偏移有助于审计，但不能将没有时区的时间戳默认视为UTC。

若某时刻当地相对UTC的偏移为 $o$ ，则：

```math
t_{\mathrm{UTC}}=t_{\mathrm{local}}-o.
```

北京时间偏移为+8小时，减8小时得到UTC。纽约的偏移随日期变化，不能全年固定减或加某个小时数。

**定位时区（Localization）**是解释一个尚无时区的本地时间；**转换时区（Conversion）**是保持同一时刻不变，换一种本地表示。把已知UTC时间直接替换tzinfo，不等于正确转换；应使用时区转换方法。

### 19.1.2 夏令时：不存在的时间和出现两次的时间

**夏令时（Daylight Saving Time，DST）**可能使本地时钟前跳或后退。

以前跳为例，本地时钟可能从01:59:59跳到03:00:00，因此某天02:30根本不存在。后退时，01:30可能出现两次，分别对应不同UTC时刻。

本章使用IANA时区数据库中的America/New_York。2026-03-08 02:30是不存在的本地时间；2026-11-01 01:30具有两个候选时刻。Python的zoneinfo支持时区转换与fold标志，但给naive datetime简单附加时区，不会自动替业务决定该如何处理歧义。[Python zoneinfo文档](https://docs.python.org/3.13/library/zoneinfo.html)

本章采用往返校验：

1. 为一个本地时间分别尝试fold=0和fold=1。
2. 转成UTC，再转回原时区。
3. 仅保留能还原原始本地钟表时间的候选。
4. 没有候选则报不存在；两个不同候选则要求明确选较早或较晚；一个候选则无歧义。

这是显式策略。不能把不存在时间静默平移到下一小时，也不能在歧义发生时随意取第一条。

IANA数据库会随着政治决定和历史资料修正更新。因此长期复现实验应固定时区数据版本或相关数据文件，而不能仅记录“使用了zoneinfo”。[IANA Time Zone Database](https://www.iana.org/time-zones)

### 19.1.3 交易日历比“周一到周五”复杂

**交易日历（Trading Calendar）**描述特定场所、特定产品在某日期是否交易、何时交易，以及特殊安排。至少区分：

- 自然日期；
- 场所定义的交易日标签；
- 开盘集合竞价、连续交易、收盘集合竞价；
- 午间休市与盘间休息；
- 节假日、提前收市、临时停市；
- 个别工具停牌；
- 夜盘所属的交易日。

节假日调休中的工作日不自动成为证券交易日。期货夜盘可能发生在前一自然日，但归入另一个交易日。股票、债券、期权和外汇也不能只因同属一个国家而共享相同日历。

上海证券交易所2026年规则发布页明确区分发布日期与生效日期，并附有暂缓实施条文。这提示工程实现不仅要保存规则内容，还要保存其生效范围，不能用今天看到的最新规则覆盖所有历史。[上交所2026年交易规则发布页](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml)

本章没有下载该规则附件全文，也不据此实现完整交易所规则引擎。

NYSE官方页面按市场和产品列示交易时段；NYSE核心交易时段通常为美国东部时间09:30—16:00，页面还列出指定日期提前收市安排。不能把其他市场、期权例外时段或盘前盘后交易混入同一连续交易段。[NYSE交易时间与日历](https://www.nyse.com/markets/hours-calendars)

### 19.1.4 用区间表达交易时段

将某日历定义的交易时段写成互不重叠区间：

```math
\mathcal S=\bigcup_{j=1}^{J}[a_j,b_j).
```

时刻 $t$ 是否位于所选交易阶段，可写成：

```math
I_{\mathrm{open}}(t)=
\begin{cases}
1,&t\in\mathcal S,\\[0pt]
0,&t\notin\mathcal S.
\end{cases}
```

本实验采用左闭右开约定，恰在结束时刻的记录不属于该段。真实收盘集合竞价可能在结束边界产生有效记录，应单独定义交易阶段和边界归属；不能照搬本实验后把正式收盘成交删掉。

午休应表现为区间之间的空隙，不能产生看似正常但全为填充价格的午休分钟K线。

对于提前收市，最后一个桶可能不足标准宽度。系统应记录实际左右端点和时长，或者明确选择不输出部分桶，不能暗中把它当成完整一分钟。

### 19.1.5 墙钟时间与交易时间

**墙钟时间（Wall-Clock Time）**是普通时间轴经过的时长。**交易时间（Trading Time）**仅累积某日历规定的交易阶段：

```math
B(t)=\int_{t_0}^{t}I_{\mathrm{open}}(u)\,du.
```

在 $s$ 到 $t$ 之间：

```math
\Delta_{\mathrm{wall}}=t-s,
\qquad
\Delta_{\mathrm{trade}}=B(t)-B(s).
```

例如人工日历11:30—13:00休市，从11:29到13:01经过92分钟墙钟时间，却只经过2分钟所选交易时间。

风险模型使用哪种时间，需要与目标一致：行情新鲜度通常不能只靠交易时间，因为午休或隔夜也会发生信息冲击；研究交易强度时则可能希望剔除闭市间隔。两种时间都应明确标注。

## 19.2 采样、重采样、异步报价与陈旧度

### 19.2.1 事件采样和固定时间采样

**事件采样（Event-Time Sampling）**按成交或报价事件逐条记录；其间隔不规则。**固定时间采样（Calendar-Time Sampling）**按预设时间网格观察状态，例如每秒一次。

这里的event-time sampling是统计采样方式，不能与流处理系统“使用事件时间计算窗口”混为一谈。

设原始事件为 $(t_i,p_i)$ ，网格为 $\tau_k$ 。最近已知值采样可写成：

```math
i^*(k)=\arg\max_{i:t_i\le\tau_k}t_i,
\qquad
\widetilde p_k=p_{i^*(k)}.
```

这个公式还缺少可用时间约束，19.3节会补上。即使补齐，它也只表示“截至该时刻最近已知价格”，不表示每个网格点发生了真实成交。

### 19.2.2 重采样必须先规定统计口径

**重采样（Resampling）**把原有时间尺度的数据转换成另一尺度。降频通常需要聚合，升频通常会引入缺失或插补。

常见金融变量应采用不同聚合方式：

| 变量 | 常见降频方法 | 主要条件 |
|---|---|---|
| 成交价 | OHLC | 明确事件顺序和窗口边界 |
| 逐笔成交量 | 求和 | 必须是增量，不是累计量 |
| 累计成交量 | 端点差分等 | 处理重置、修订及首值 |
| 对数收益 | 求和 | 连续区间、相同价格口径 |
| 简单收益 | 连乘后减1 | 不能直接当作精确可加 |
| 利率、价差 | 末值或时间加权平均 | 取决于用途 |
| 宏观季度总量 | 保留季度口径 | 不能复制成每月新观测 |

**OHLC**分别表示开盘价Open、最高价High、最低价Low和收盘价Close。某时间桶内按真实事件顺序排列价格 $p_1,\ldots,p_n$ ：

```math
O=p_1,\quad H=\max_i p_i,\quad L=\min_i p_i,\quad C=p_n.
```

本章成交量 $v_i$ 是逐笔增量，因此：

```math
V=\sum_i v_i.
```

若原始字段是累计成交量，直接相加会严重重复计数。没有成交的桶应保留价格为空；程序输出volume=0仅表示“当前已知输入没有增量成交”，不证明供应商没有漏报。

### 19.2.3 收益聚合的推导

相邻简单收益定义为：

```math
1+r_i=\frac{P_i}{P_{i-1}}.
```

连乘后中间价格相消：

```math
\prod_{i=1}^{m}(1+r_i)
=\frac{P_1}{P_0}\frac{P_2}{P_1}\cdots\frac{P_m}{P_{m-1}}
=\frac{P_m}{P_0}.
```

因此累计简单收益为：

```math
R=\prod_{i=1}^{m}(1+r_i)-1.
```

对数收益为 $\ell_i=\log P_i-\log P_{i-1}$ ，求和可得：

```math
\sum_{i=1}^{m}\ell_i=\log P_m-\log P_0.
```

这里要求价格口径和资产身份一致，且不存在被错误拼接的换月、拆股或币种变化。前向填充出来的中间零收益并不揭示真实路径，端点累计收益也不能提供缺失期实现波动率。

### 19.2.4 桶标签、边界与可用时间是三个字段

设固定宽度为 $\Delta$ ，桶为：

```math
W_k=[a+k\Delta,\ a+(k+1)\Delta).
```

标签可以选左端或右端，但标签本身不决定成员归属。标为09:31的K线，可能代表09:30—09:31，也可能代表09:31—09:32，必须看协议。

再考虑延迟：09:30:40发生的成交在09:31:20才到达。它属于09:30—09:31桶，但不能进入09:31:00时已经发布的首版聚合。

因此至少分别保存：

- bucket_start、bucket_end；
- 截至查询时间asof；
- 实际计算完成或发布时刻；
- 输入事件标识及版本；
- 是否允许后续修订。

**窗口已经结束不等于输入已经完整。**水位线是流处理系统在延迟策略下推进事件时间进度的机制，不是所有未来迟到数据绝对不再出现的证明。详细语义留到流计算章节，本章只保存不同截至时点的聚合版本。

### 19.2.5 异步采样怎样改变相关性

设两个资产真实的一期变化满足：

```math
X_t=\varepsilon_t,
\qquad
Y_t=\varepsilon_t,
```

其中冲击独立同分布、均值零、方差为 $\sigma^2\gt 0$ 。真实同期相关系数为1。

若第二项资产观测延迟一格，错误对齐后的值是 $\widetilde Y_t=\varepsilon_{t-1}$ 。则：

```math
\mathrm{Cov}(X_t,\widetilde Y_t)
=E[\varepsilon_t\varepsilon_{t-1}]=0.
```

因为两者方差仍为 $\sigma^2$ ，错误同期相关为零；但：

```math
\mathrm{Corr}(X_t,\widetilde Y_{t+1})=1.
```

于是数据延迟制造出“第一项资产领先第二项”的表象。真实金融序列不必独立同分布，也不保证简单平移就能修正；这个反例只说明对齐错误足以改变结论。

高频分析需结合持续时间、微观结构和非同步交易机制，不能把更密采样自动等同于更可靠的相关估计。[Tsay作者教学资源，第5章](https://faculty.chicagobooth.edu/ruey-s-tsay/research/analysis-of-financial-time-series-3rd-edition)

### 19.2.6 两种年龄不能混淆

对已选记录，事件时间为 $t_i$ ，可用时间为 $a_i$ ，决策时点为 $\tau$ ：

```math
A_{\mathrm{event}}=\tau-t_i,
\qquad
A_{\mathrm{available}}=\tau-a_i.
```

若交易发生在10:00，10:10才到达，10:10:01查询时，可用年龄仅1秒，事件年龄却为601秒。把接收很新误当行情很新，会在断流恢复时误报当前市场状态。

本章用事件年龄限制实时价格，并保留记录ID和年龄用于解释。状态分为LIVE、STALE、MISSING和CLOSED：

- LIVE：当前交易段存在合格、未超龄记录；
- STALE：存在记录，但超过年龄限制；
- MISSING：处于交易段，却没有该段可见记录；
- CLOSED：不处于实验选择的交易段。

CLOSED不等于数据服务正常；服务连接状态还需另行监控。

## 19.3 可用信息驱动的跨频率连接

### 19.3.1 因果连接的完整条件

**截至连接（As-of Join）**是在某一查询时点选择满足时间条件的记录。设记录资产为 $b_i$ ，事件时间为 $t_i$ ，可用时间为 $a_i$ ，目标资产为 $b$ ，查询时点为 $\tau$ 。

当前交易段为 $S(\tau)$ 时，候选集合为：

```math
\mathcal C_b(\tau)=
\lbrace i:b_i=b,\ a_i\le\tau,\ t_i\le\tau,\ t_i\in S(\tau)\rbrace.
```

在候选中按事件时间和来源内序号选择最新记录，再检查：

```math
0\le\tau-t_{i^*}\le\delta.
```

这里 $\delta$ 是事先设定的最大陈旧度。多个同事件时刻记录应有明确顺序或版本契约；不能依赖数据库任意返回顺序。

为什么不是选“最后到达”的记录？较早发生的事件可能迟到。迟到事件应更新其历史桶，但未必应改变当前最新价格。

### 19.3.2 merge_asof的能力与边界

pandas的merge_asof可按backward、forward或nearest寻找时间邻近记录，要求连接键升序，并支持分组和tolerance。[官方API](https://pandas.pydata.org/docs/reference/api/pandas.merge_asof.html)

但：

- 按事件时间backward连接，不会自动检查可用时间。
- 按可用时间backward连接，可能选中迟到的旧事件。
- nearest可能选未来值。
- tolerance约束的是所选连接键差值，未必是事件年龄。
- 交易段、版本与资产分组仍需额外定义。

只有在事件时间与可用时间顺序满足额外条件、并且所有约束都已处理时，一次简单连接才可能等价于目标查询。一般情况应先限定可见信息，再维护每资产最新事件状态。

### 19.3.3 同日跨市场收盘价为何可能泄漏

假设在上海当地15:00作决策。此时UTC为07:00。纽约同一当地日期的16:00收盘通常尚未发生，更未被本平台获取。若按“日期”把两者合并，就可能使用未来收盘价。

正确做法是围绕决策时刻建立信息集：美国市场可以使用当时已经可见的上一交易时段记录，并明确标注它的年龄和市场闭市状态；是否允许这种跨时段引用取决于模型契约。

本实验选择严格不跨交易段携带报价，便于展示差异；这不是唯一合理政策。跨市场资产配置可能需要最近已知收盘，但必须保留独立时间戳，不能声称这些收盘完全同步。

### 19.3.4 宏观低频信息与高频行情

将月度宏观数值重复到每分钟，并不创造新的宏观观测。需要分别保存统计期、首次发布时间、修订版本、可用时间和距离发布经过多久。

例如9月指标10月公布，不能从9月第一天就填入整个9月行情。宏观值在发布后作为状态变量向前持有，与把未来公布值向后填入统计期，是相反方向的操作。

文本特征也一样：新闻发布、系统接收和情绪计算完成可能各不相同。只有特征完成后才能进入在线面板。多频率对齐必须传递这些时间条件，而不是把全部数据统一成日期字符串。第20章将建立完整PIT和双时间查询体系。

### 19.3.5 复杂度与部署策略

直接对每个查询扫描全部事件，复杂度约为 $O(QN)$ ，其中 $Q$ 为查询数、 $N$ 为输入事件数，适合小型验证基准。

生产中可按可用时间推进事件流，同时为各资产维护按事件时间及序号排序的最新状态；窗口聚合则维护对应事件桶。迟到数据可更新旧桶，但当前状态不倒退。需要历史任意时点查询时，还应保留快照、版本账本或索引。

不能仅用一个“最后收到的字典”同时承担当前快照和历史聚合的全部职责。

```python
import hashlib
import json
from datetime import datetime, timedelta, timezone
from pathlib import Path
from zoneinfo import ZoneInfo, TZPATH

UTC = timezone.utc


def instant(text):
    dt = datetime.fromisoformat(text.replace("Z", "+00:00"))
    if dt.tzinfo is None:
        raise ValueError("Timezone required")
    return dt.astimezone(UTC)


def local_candidates(text, zone):
    naive = datetime.fromisoformat(text)
    if naive.tzinfo is not None:
        raise ValueError("Expected local wall time without offset")
    tz = ZoneInfo(zone)
    values = set()
    for fold in (0, 1):
        local = naive.replace(tzinfo=tz, fold=fold)
        utc = local.astimezone(UTC)
        if utc.astimezone(tz).replace(tzinfo=None) == naive:
            values.add(utc)
    return sorted(values)


def local_instant(text, zone, choice=None):
    candidates = local_candidates(text, zone)
    if not candidates:
        raise ValueError("Nonexistent local time")
    if len(candidates) == 2 and choice is None:
        raise ValueError("Ambiguous local time: choose earlier or later")
    if choice not in (None, "earlier", "later"):
        raise ValueError("Invalid choice")
    return candidates[-1] if choice == "later" else candidates[0]


def sessions():
    # Deliberately tiny synthetic calendar, NOT an exchange holiday calendar.
    return [
        dict(id="AM", day="2026-10-29", start=instant("2026-10-29T01:30:00Z"),
             end=instant("2026-10-29T03:30:00Z")),
        dict(id="PM", day="2026-10-29", start=instant("2026-10-29T05:00:00Z"),
             end=instant("2026-10-29T07:00:00Z"))]


def session_at(t, calendar):
    found = [s for s in calendar if s["start"] <= t < s["end"]]
    if len(found) > 1:
        raise ValueError("Overlapping calendar intervals")
    return found[0] if found else None


def validate(rows):
    ids = set()
    for r in rows:
        if r["id"] in ids or r["available"] < r["event"]:
            raise ValueError("Duplicate ID or impossible availability")
        if r["price"] <= 0 or r["volume"] < 0:
            raise ValueError("Invalid synthetic trade")
        ids.add(r["id"])


def snapshot(rows, asset, cutoff, calendar, tolerance):
    if tolerance.total_seconds() < 0:
        raise ValueError("Negative tolerance")
    current = session_at(cutoff, calendar)
    if current is None:
        return dict(status="CLOSED", id=None, price=None, age=None)
    visible = [r for r in rows if r["asset"] == asset
               and r["available"] <= cutoff and r["event"] <= cutoff
               and current["start"] <= r["event"] < current["end"]]
    if not visible:
        return dict(status="MISSING", id=None, price=None, age=None)
    selected = max(visible, key=lambda r: (r["event"], r["seq"], r["id"]))
    age = (cutoff-selected["event"]).total_seconds()
    stale = age > tolerance.total_seconds()
    return dict(status="STALE" if stale else "LIVE", id=selected["id"],
                price=None if stale else selected["price"], age=age)


def bars(rows, asset, cutoff, calendar, width=timedelta(minutes=1)):
    if width.total_seconds() <= 0:
        raise ValueError("Positive width required")
    result = []
    for session in calendar:
        left = session["start"]
        while left < session["end"]:
            right = min(left+width, session["end"])
            if right > cutoff:
                break  # Do not label a still-open bucket as a completed bar.
            eligible = sorted(
                [r for r in rows if r["asset"] == asset and left <= r["event"] < right
                 and r["available"] <= cutoff],
                key=lambda r: (r["event"], r["seq"], r["id"]))
            prices = [r["price"] for r in eligible]
            result.append(dict(session=session["id"], left=left, right=right,
                asof=cutoff, count=len(eligible),
                open=prices[0] if prices else None, close=prices[-1] if prices else None,
                high=max(prices) if prices else None, low=min(prices) if prices else None,
                volume=sum(r["volume"] for r in eligible),
                inputs=[r["id"] for r in eligible]))
            left = right
    return result


def samples():
    base = instant("2026-10-29T01:30:00Z")
    rows = []
    def add(asset, name, event, available, price, volume, seq):
        rows.append(dict(asset=asset, id=name, event=base+timedelta(seconds=event),
                         available=base+timedelta(seconds=available), price=price,
                         volume=volume, seq=seq))
    add("EQ_DEMO", "q1", 10, 11, 100, 2, 1)
    add("EQ_DEMO", "q2", 40, 80, 102, 3, 2)  # Late arrival changes old bar.
    add("EQ_DEMO", "q3", 60, 61, 101, 4, 3)  # Exactly on next bar boundary.
    add("EQ_DEMO", "q4", 70, 71, 103, 1, 4)
    add("BOND_DEMO", "b1", 15, 16, 99, 5, 1)
    add("GOLD_DEMO", "g1", 20, 100, 2000, 1, 1)
    add("FX_DEMO", "f1", 5, 6, 7, 100, 1)
    return rows


def run():
    rows, calendar = samples(), sessions()
    validate(rows)
    base = calendar[0]["start"]
    cuts = [base+timedelta(seconds=t) for t in (60, 75, 90, 120)]
    panels = [dict(at=t, values={a:snapshot(rows,a,t,calendar,timedelta(seconds=60))
                 for a in ("EQ_DEMO","BOND_DEMO","GOLD_DEMO","FX_DEMO")}) for t in cuts]
    dst = {day:local_instant(day+"T09:30:00","America/New_York")
           for day in ("2026-03-06","2026-03-09")}
    return dict(data_kind="SYNTHETIC", input=rows, calendar=calendar,
                dst=dst, panel=panels,
                first_bar=[bars(rows,"EQ_DEMO",t,calendar)[0] for t in (cuts[0],cuts[2])])


def main():
    root=Path(__file__).parent
    out=root/"runs"/datetime.now(UTC).strftime("run_%Y%m%dT%H%M%S_%fZ")
    out.mkdir(parents=True)
    result=run()
    path=out/"results.json"
    path.write_text(json.dumps(result,default=lambda x:x.isoformat(),indent=2)+"\n",encoding="utf-8")
    manifest=dict(calendar_version="DEMO-20261029-v1", timezone_paths=list(TZPATH),
                  code_sha256=hashlib.sha256(Path(__file__).read_bytes()).hexdigest(),
                  results_sha256=hashlib.sha256(path.read_bytes()).hexdigest())
    # Record installed tzdata package version if the environment provides it.
    from importlib.metadata import version, PackageNotFoundError
    try:
        manifest["tzdata_package"]=version("tzdata")
    except PackageNotFoundError:
        manifest["tzdata_package"]=None
    (out/"manifest.json").write_text(json.dumps(manifest,indent=2)+"\n",encoding="utf-8")
    print(json.dumps(dict(dst=result["dst"],first_bar=result["first_bar"]),default=str,indent=2))
    print(out.resolve())


if __name__=="__main__":
    main()
```

### 19.4.4 机制、测试与限制

local_candidates通过UTC往返排除不存在的本地时间，并要求歧义时间显式选边。所有内部比较都转换到UTC，避免重复钟表时间的误比较。

snapshot先限定截至时点可见记录和当前交易段，再取最大事件时间；bars按事件时间划桶，同时按可用时间筛选。两者的排序目的不同。

bars只输出右端点已到的桶，但不声称这些桶已经最终完整。asof记录的是查询信息截止时点；实际部署中还需单独记录计算结束与服务发布时刻。代码没有实现水位线、自动推送修订、成交撤销或业务版本合并。

12项测试覆盖偏移等价、无时区拒绝、DST转换、不存在和重复时间、开闭边界、迟到不回滚、陈旧和缺失、不跨午休携带、K线边界及修订、未来扰动不影响过去、未完成桶及空桶、重复ID拒绝、缩短交易段裁剪。某个测试函数覆盖多个断言，不能把断言数冒充独立测试数。

扫描式实现易核验但不适合高吞吐生产。代码对每个桶扫描输入，再排序选中事件；其代价可近似写成 $O(BN+N\log N)$ （固定资产且事件只落入一个桶时），其中 $B$ 为桶数。实际服务应预分桶并增量更新，同时保留同样的截至时点语义。

## 本章总结

时区转换、交易日历和信息可用性是三个不同层次。UTC统一时刻，日历定义业务交易段，可用时间约束决策能够看到什么；任何一个层次都不能替代另两个。

重采样必须声明变量口径、桶端点及标签。迟到事件可以修订旧K线，却不应让当前最新价格倒退。跨市场按日期合并和按事件时间简单后向连接，都可能引入未来信息。

本章完成了时区、交易段、异步快照与迟到聚合的可运行实验。下一章将把这些原则扩展为完整的金融数据时间有效性与PIT安全体系。

## 详细参考答案

### 1. 定位与转换

定位时区是为钟表读数提供解释，例如把09:30解释为上海时间。转换时区是同一时刻从UTC显示为上海时间，此时01:30 UTC显示为09:30上海。

若把01:30 UTC直接替换成Asia/Shanghai的01:30，实际变成前一天17:30 UTC，时刻改变了8小时。转换应使用astimezone；定位还需检查DST歧义。

### 2. 三个集合

政府安排的调休周末工作日不自动成为交易所交易日；交易日中某资产可能停牌，没有正常连续交易；非正常交易时段收到的迟到消息也不说明那个接收日期就是对应业务交易日。因此需要日历、资产状态和事件来源共同判断。

### 3. 纽约与北京时间

偏移−5时：

```math
09{:}30+5\text{小时}=14{:}30\ \mathrm{UTC},
\qquad14{:}30+8\text{小时}=22{:}30.
```

偏移−4时为13:30 UTC、21:30北京时间。日期跨越时应一并调整日期，不能仅对小时取模而丢弃日期变化。

### 4. 两种时长

墙钟时长92分钟。交易时长包括上午11:29—11:30的1分钟、下午13:00—13:01的1分钟，总计2分钟。中间90分钟是否纳入某个模型的衰减尺度，取决于模型目标，不是时间函数能代替业务做的选择。

### 5. 两期收益

```math
R=(1+0.1)(1-0.1)-1=0.99-1=-0.01.
```

累计简单收益−1%。累计对数收益为：

```math
\ell=\log(1.1)+\log(0.9)=\log(0.99)\approx-0.01005034.
```

简单相加得到零，遗漏了乘积交叉项−0.01。只有在变动足够小时，加法才可能是近似。

### 6. 延迟与相关

真实同一期变量完全相同，协方差等于方差，因此相关1。错位后取独立的相邻冲击，乘积期望为零，均值也为零，因此协方差0、相关0。

这只是在特定生成假设下的反例，不能据此断言真实市场的异步相关必为零，更不能据此排除真实联动或因果机制。应先核查观测时刻和可用时刻，再研究经济关系。

### 7. 当前价选择

90秒时两条记录都可见。q4事件时间70秒，比q2的40秒更新，因此当前价应来自q4。按最大可用时间会因80大于71而误选q2，把状态倒退。

但是在[0,60)的历史桶中，q2应被纳入90秒时重新计算的新版聚合。一个事件对当前快照和历史K线的作用可以不同。

### 8. 边界归属

01:31:00属于[01:31:00,01:32:00)，不属于[01:30:00,01:31:00)。真实收盘集合竞价应有明确阶段标识及协议定义的边界处理，例如单独的auction事件或专门收盘桶；不能因默认半开区间丢弃正式收盘成交，也不能让同一成交进入两个桶。

### 9. 编程验证

在ch19目录运行：

```python
import copy
from datetime import timedelta
import alignment_lab as lab

rows = lab.samples()
changed = copy.deepcopy(rows)
calendar = lab.sessions()
cutoff = calendar[0]["start"] + timedelta(seconds=60)
for row in changed:
    if row["available"] > cutoff:
        row["price"] *= 100

args = ("EQ_DEMO", cutoff, calendar, timedelta(seconds=60))
assert lab.snapshot(rows, *args) == lab.snapshot(changed, *args)
assert lab.bars(rows, "EQ_DEMO", cutoff, calendar) == lab.bars(
    changed, "EQ_DEMO", cutoff, calendar
)
print("Future inputs do not change the earlier snapshot or bar.")
```

该测试改变未来输入的数值，而不只检查它们没有被显式输出；因此能发现某些提前参与聚合或选取的泄漏。

### 10. 月频指标连接

本平台10月16日才接入，因此10月15日模型不能使用该数据，即使它已公开发布。若声称另一个渠道当日已获取，必须有相应证据，不能事后猜测。

转成日频时应保留原统计期“9月”、发布日期、实际可用时间和版本；在可用后按明确政策持有该信息，同时记录距离发布或统计期的年龄。每天重复同一值不意味着每天都有一次新的独立宏观观测。

### 11. 日历模型

可采用calendar_id、venue、product_group、trading_day、session_id、phase、local_timezone、start_utc、end_utc、boundary_policy、status、version、known_at及evidence_id。

夜盘通过trading_day与自然日期分离表达；午休用多个交易段表达；临时停市或提前收市新增带获知时间的版本。资产级停牌应有单独状态表，而不是修改整个交易所日历。

验收应覆盖区间不重叠、边界无重复、版本有效范围、DST往返一致、历史查询只使用当时已知日历。对尚未公布的特殊安排不能提前纳入在线重放。

### 12. 面板验收

至少包括：

1. 所有输入时间带明确时区，内部比较采用UTC。
2. 每列均满足可用时间不晚于决策时刻。
3. 事件年龄与获取年龄分开，超龄值明确标记。
4. 不将闭市、缺失、陈旧和服务故障合为同一状态。
5. 迟到旧事件不回滚当前价格，但可产生旧桶修订版本。
6. 桶边界、集合竞价和提前收市有明确归属。
7. 不按同一日期提前使用其他市场未来收盘。
8. 原始输入、日历版本、规则和计算完成时间可追溯。
9. 改变未来输入不影响此前已发布结果。
10. 正常值与异常、空值在前端可区分，历史重述不冒充原实时输出。

开放题不要求唯一架构，但必须能给出验证数据和失败时的具体行为。
