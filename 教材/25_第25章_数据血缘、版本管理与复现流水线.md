## 25.1 数据、代码、参数和环境的版本关系

### 25.1.1 结果不是代码一个变量的函数

设数据快照D、程序C、参数P、环境E、随机状态S、时间协议T共同决定输出：

```math
O=F(D,C,P,E,S,T).
```

只保存随机种子不足以复现：原始数据可能被修订，库版本可能改变默认值，多线程归约顺序也可能变化。只保存Git提交也不足够：工作区可能有未提交修改，输入文件和外部服务不在Git中。

最小实验清单应包含：输入身份与行数、PIT截止、代码及未提交改动状态、参数、环境、随机生成器、输出校验和、开始/完成时间、运行状态及错误类别。与凭证无关的环境信息可以登记，但不能把整个环境变量表和访问令牌打包进报告。

**数据血缘（Data Lineage）**描述数据如何由来源经过活动产生；**来源追溯（Provenance）**还关注参与活动和责任主体。W3C PROV以实体、活动和代理等概念表达这类关系，不等于一个特定数据库产品。[W3C PROV概览](https://www.w3.org/TR/prov-overview/)

### 25.1.2 三种身份

运行ID标识一次尝试，即使参数相同，失败后重试也可以是新运行。计算身份描述“要求执行的计算”；产物身份描述“实际得到的字节”。它们必须分开。

令H为SHA-256，canon为明确的序列化约定，计算键可写成：

```math
K=H(\mathrm{canon}(H(D),H(C),P,E,S,T)).
```

产物身份为：

```math
A=H(\mathrm{bytes}(O)).
```

相同计算键在确定性假设下应产生相同内容；不同计算键也可能产生相同输出。例如只修改未来不可用行，过去截止下的均值不变，但输入快照身份改变。这是合理现象，不应强迫两个概念相等。

时间戳、随机运行ID不要混入需要稳定复用的结果正文；它们属于运行元数据。否则即使计算完全一样，字节哈希也会每次变化。

### 25.1.3 规范化、精度与哈希边界

JSON对象键顺序、空格、换行和编码都影响字节。实验使用UTF-8、键排序、紧凑分隔符和禁止NaN，并用字符串表示十进制输入。

这只是本项目的序列化契约，不是实现了所有语言通用的标准规范化JSON。列表顺序仍保留，Unicode规范化和数字字符串“2”与“2.0”也没有自动统一；这些可能影响语义或缓存粒度，必须主动定义。

十进制计算也受精度、舍入和异常策略影响。本例在局部上下文中固定28位有效数字，避免其他代码修改全局上下文影响结果。[Python decimal官方文档](https://docs.python.org/3.13/library/decimal.html)

在理想均匀b位哈希假设下，N个对象发生碰撞的联合上界由每对碰撞概率相加得到：

```math
P(\mathrm{collision})\leq\frac{N(N-1)}{2^{b+1}}.
```

这只是概率模型。实际工程仍需校验已有同键内容，使用成熟密码学哈希，而非语言内置hash函数。

哈希能发现“字节与预期摘要不一致”，不证明来源真实。攻击者若能同时改数据、清单和被信任的根摘要，普通哈希无法阻止。防篡改还需独立可信根、权限、签名或只追加存储等设计。

### 25.1.4 环境记录的层次

Python和库版本是起点，数值模型还可能依赖BLAS、CUDA、设备、线程数、时区数据库、交易日历和外部模型修订。环境清单是描述，锁定文件帮助重建，容器镜像提供更多打包保障，但容器也不自动固定外部数据和硬件行为。

使用现有Anaconda记录实际环境，不为教材重复下载Python。缺库时应先确认需要，不在运行脚本中静默安装最新版。演示依赖越少越容易理解，但生产也不应为了“纯标准库”重写成熟数据库或分布式协议。

## 25.2 数据集快照、血缘图与实验清单

### 25.2.1 快照是内容与查询语义的组合

**快照（Snapshot）**指可以稳定引用的一组版本或字节。一个名字叫latest.csv的路径不是稳定快照。SQL查询文本相同也不代表结果相同：底表可能变化，缺少ORDER BY时返回顺序可能改变。

行情快照应说明资产集合、收益口径、时段、交易日历、版本选择和知识截止。宏观快照还需首次值/修订值政策，新闻快照需撤回及转载规则。

本例输入含全部人工行，其中有截止后才可用的行；清单记录整个研究输入快照，计算仅选ready不晚于cutoff的记录。这是离线PIT回放，不声称当时线上系统已持有未来行。改变未来行会改变快照键，但不会改变过去结果。

### 25.2.2 血缘图与依赖闭包

将不可变数据实体和计算活动连成**有向无环图（Directed Acyclic Graph，DAG）**：原始快照→清洗活动→特征快照→训练活动→模型→推理结果。图描述逻辑依赖；一次活动可以有多个输入和输出。

只保存直接父节点不足以复现下游；还需要能够追溯到全部祖先。删除某个上游快照前，应检查是否仍被保留模型或历史报告引用。

若输入节点改变，需要重算的是其受影响后代，未依赖该输入的分支可以保留。缓存键必须包含相关父节点身份；遗漏交易日历或词典版本，就会错误复用。

OpenLineage区分数据集、作业及运行事件，有助于跨工具交换血缘；记录了事件不代表已经保证结果确定性。[官方对象模型](https://openlineage.io/docs/spec/object-model/)

### 25.2.3 数据库约束与清单

本例用三个表：artifacts保存摘要和原始字节；runs保存尝试与状态；edges将输入、代码、参数、输出和汇总清单关联。清单引用各产物哈希，阅读时逐个复核。

成功计算键使用部分唯一索引，允许失败后新尝试，但不允许同一计算键存在两份成功记录。外键开启后可防止边引用不存在实体，但不能验证全部金融语义。

本例edges表示整次活动的输入/输出成员关系，没有实现每个列和每一行的完整细粒度血缘。若模型输入某一列来自复权价格，应进一步保存列级变换和源版本，不能把粗粒度图宣传为已经解决全部追溯。

### 25.2.4 工具的职责边界

Git适合代码、配置和较小文档；大行情数据可放版本化对象存储，Git只保存清单。MLflow Tracking记录实验参数、指标、代码版本和产物，但记录工具本身不替代PIT或事务设计。[MLflow官方说明](https://mlflow.org/docs/latest/ml/tracking/)

DVC等工具可管理数据依赖及复现流程，但本次相关官方页面访问失败，故不据未读页面说明具体命令或字段。本章不安装这些系统，而用可检查的最小实现呈现共同概念。

小型竞赛可以先用文件清单和SQLite；多人共享、海量数据和持续部署再引入对象存储、实验跟踪与血缘服务。选型应由规模、协作和恢复要求决定。

## 25.3 幂等流水线、历史重算与复现验收

### 25.3.1 幂等不等于只执行一次

**幂等（Idempotence）**意味着相同请求重复施加后，业务可观察状态与一次施加相同。若状态变换为G_k：

```math
G_k(G_k(s))=G_k(s).
```

本例同计算键的成功请求复用已校验产物，不新建成功运行。失败后重试可以产生新的尝试ID，最终业务产物仍相同。

这不意味着底层CPU只执行一次，也不证明跨Kafka、数据库和邮件服务具有端到端Exactly-once。外部副作用需业务幂等键、事务发件箱或接收端去重；未来微服务篇再实现。

### 25.3.2 状态机与原子发布

基本状态为RUNNING、SUCCESS、FAILED。先登记RUNNING，再计算；只有产物、血缘和成功状态在同一事务提交后，消费者才可读取成功结果。

若先写SUCCESS、再逐个写文件，消费者可能看到半套结果。本例把小产物字节与元数据放在同一SQLite事务中，使提交或回滚覆盖它们。[SQLite原子提交说明](https://www.sqlite.org/atomiccommit.html)

计算失败后将尝试标为FAILED，保留错误类型。真正进程被杀可能留下RUNNING，不能假装异常处理一定执行。生产应增加心跳、租约、超时与恢复任务，并避免旧工作者在租约过期后覆盖新结果。

对象存储与元数据库通常不能共享一个本地事务。可以先写不可变对象、校验，再原子发布清单指针；未发布对象作为待清理孤儿保留。删除时检查引用与宽限期，不能只按文件年龄清空。

### 25.3.3 三种历史运行

**原样重放**使用原始数据快照、代码和参数，目标是重建旧输出。

**修正重算**使用纠正后的代码或数据，产生新结果并关联原运行，不能覆盖旧报告。

**最新知识研究**使用后来修订的数据回答研究问题，必须明确其不等于当时在线可得结果。

同一日期出现不同结果可能是版本不同，不一定是程序错误；同一完整计算身份出现不同结果则需要调查未记录依赖或非确定性。

### 25.3.4 复现的三级验收

字节级复现要求产物摘要相同；数值复现允许预先约定误差：

```math
|a-b|\leq\varepsilon_{\mathrm{abs}}+
\varepsilon_{\mathrm{rel}}\max(|a|,|b|).
```

这是本章选用的加法容差定义，不与其他库的公式混用。第三层是业务语义一致，例如记录选择和告警决策一致。数值接近不保证阈值两侧的决策一致。

容差必须在看到差异之前确定。排序、精度、舍入、随机性和硬件都应逐层排查。只重跑缓存命中路径不算独立复算，应在新存储中重新执行，再比较结果。

复现也不等于正确：错误代码可以稳定产生相同错误。需要独立手算、参考实现、PIT边界、失败注入和损坏检查。

## 25.4 完整实验：内容寻址与事务式流水线

### 25.4.1 输入、结果和安全边界

三条人工记录a、b、c的ready分别为1、3、8，值为1、3、8。截止3选择a、b，均值2；截止8选择全部，均值4。固定规则是严格大于阈值2才HIGH，因此前者LOW、后者HIGH；无可用数据时UNKNOWN。

程序保存完整输入、代码源文件、计算配方、选择结果、排除审计和输出。缓存读取验证全部清单成员，发现损坏则报错，不默默重算并掩盖证据。操作范围限定于每次新建的runs目录。

### 25.4.2 完整代码与SQL

[程序](./code/ch25/lineage_lab.py)内含完整SQL，配套[测试](./code/ch25/test_lineage_lab.py)使用内存数据库，不删除用户数据库。实验依赖只有标准库，数据为教学自建。

```python
"""SYNTHETIC lineage lab. Standard library, single-process SQLite."""
from pathlib import Path
from datetime import datetime, timezone
from decimal import Decimal, Context, localcontext
import hashlib
import json
import platform
import sqlite3
import uuid

SCHEMA = '''
CREATE TABLE IF NOT EXISTS artifacts(
 hash TEXT PRIMARY KEY, body BLOB NOT NULL);
CREATE TABLE IF NOT EXISTS runs(
 id TEXT PRIMARY KEY, recipe_hash TEXT NOT NULL, status TEXT NOT NULL,
 manifest_hash TEXT, error TEXT);
CREATE UNIQUE INDEX IF NOT EXISTS one_success ON runs(recipe_hash)
 WHERE status='SUCCESS';
CREATE TABLE IF NOT EXISTS edges(
 run_id TEXT NOT NULL REFERENCES runs(id), parent TEXT NOT NULL REFERENCES artifacts(hash),
 child TEXT NOT NULL REFERENCES artifacts(hash), role TEXT NOT NULL,
 PRIMARY KEY(run_id,parent,child,role));
'''

def canonical(value):
    return json.dumps(value, sort_keys=True, separators=(',', ':'),
                      ensure_ascii=False, allow_nan=False).encode('utf-8')

def digest(body):
    return hashlib.sha256(body).hexdigest()

def connect(path):
    db = sqlite3.connect(path)
    db.execute('PRAGMA foreign_keys=ON')
    db.executescript(SCHEMA)
    return db

def put(db, body):
    key = digest(body)
    old = db.execute('SELECT body FROM artifacts WHERE hash=?', (key,)).fetchone()
    if old is not None and bytes(old[0]) != body:
        raise ValueError('existing artifact corrupted or collision')
    db.execute('INSERT OR IGNORE INTO artifacts VALUES (?,?)', (key, body))
    return key

def read(db, key):
    row = db.execute('SELECT body FROM artifacts WHERE hash=?', (key,)).fetchone()
    if row is None or digest(bytes(row[0])) != key:
        raise ValueError('missing or corrupted artifact')
    return bytes(row[0])

def verify(db, manifest_hash):
    manifest = json.loads(read(db, manifest_hash))
    for key in manifest['artifacts'].values():
        read(db, key)
    recipe = json.loads(read(db, manifest['artifacts']['recipe']))
    if recipe['raw'] != manifest['artifacts']['raw'] or recipe['code'] != manifest['artifacts']['code']:
        raise ValueError('lineage mismatch')
    return json.loads(read(db, manifest['artifacts']['result']))

def compute(raw, cutoff, threshold):
    rows = json.loads(raw)
    if len({r['id'] for r in rows}) != len(rows):
        raise ValueError('duplicate row id')
    selected, audit = [], []
    for row in rows:
        if not isinstance(row['ready'], int):
            raise ValueError('ready must be integer')
        value = Decimal(row['value'])
        if not value.is_finite():
            raise ValueError('nonfinite value')
        if row['ready'] <= cutoff:
            selected.append(row)
        else:
            audit.append({'id': row['id'], 'reason': 'NOT_YET_AVAILABLE'})
    selected.sort(key=lambda r: r['id'])
    with localcontext(Context(prec=28)):
        mean = sum((Decimal(r['value']) for r in selected), Decimal(0))/len(selected) if selected else None
    result = {'cutoff': cutoff, 'mean': str(mean) if mean is not None else None,
              'state': 'UNKNOWN' if mean is None else ('HIGH' if mean > threshold else 'LOW'),
              'selected_ids': [r['id'] for r in selected]}
    return selected, audit, result

def pipeline(db, raw, cutoff, threshold='2', fail=False):
    bound = Decimal(threshold)
    if not bound.is_finite() or not isinstance(cutoff, int):
        raise ValueError('invalid configuration')
    code = Path(__file__).read_bytes()
    recipe = {'schema': 1, 'raw': digest(raw), 'code': digest(code),
              'parameters': {'cutoff': cutoff, 'threshold': threshold},
              'environment': {'python': platform.python_version(),
                              'sqlite': sqlite3.sqlite_version, 'decimal_context': 'prec=28,rounding=ROUND_HALF_EVEN'},
              'semantics': 'ready_le_cutoff_decimal_v1'}
    recipe_body = canonical(recipe)
    key = digest(recipe_body)
    cached = db.execute("SELECT manifest_hash FROM runs WHERE recipe_hash=? AND status='SUCCESS'", (key,)).fetchone()
    if cached:
        return {'cached': True, 'recipe_hash': key, 'manifest_hash': cached[0],
                'result': verify(db, cached[0])}
    run_id = str(uuid.uuid4())
    with db:
        db.execute('INSERT INTO runs VALUES (?,?,?,NULL,NULL)', (run_id,key,'RUNNING'))
    try:
        selected, audit, result = compute(raw, cutoff, bound)
        with db:
            artifacts = {'raw': put(db,raw), 'code': put(db,code),
                         'recipe': put(db,recipe_body), 'selected': put(db,canonical(selected)),
                         'audit': put(db,canonical(audit)), 'result': put(db,canonical(result))}
            manifest = put(db,canonical({'schema':1,'artifacts':artifacts}))
            for role, parent in artifacts.items():
                db.execute('INSERT INTO edges VALUES (?,?,?,?)', (run_id,parent,manifest,role))
            if fail:
                raise RuntimeError('injected failure before commit')
            db.execute("UPDATE runs SET status='SUCCESS',manifest_hash=? WHERE id=?", (manifest,run_id))
        return {'cached': False, 'recipe_hash':key,'manifest_hash':manifest,'result':result}
    except Exception as exc:
        with db:
            db.execute("UPDATE runs SET status='FAILED',error=? WHERE id=?", (type(exc).__name__,run_id))
        raise

def sample():
    return canonical([{'id':'a','ready':1,'value':'1'},
                      {'id':'b','ready':3,'value':'3'},
                      {'id':'c','ready':8,'value':'8'}])

def main():
    out=Path(__file__).parent/'runs'/datetime.now(timezone.utc).strftime('run_%Y%m%dT%H%M%S_%fZ')
    out.mkdir(parents=True)
    db=connect(out/'lineage.sqlite')
    a=pipeline(db,sample(),3)
    b=pipeline(db,sample(),3)
    c=pipeline(db,sample(),8)
    report={'data_kind':'SYNTHETIC','first':a,'retry':b,'later':c,
            'integrity':db.execute('PRAGMA integrity_check').fetchone()[0]}
    (out/'report.json').write_bytes(canonical(report))
    db.close()
    print(out)
    print(json.dumps(report,ensure_ascii=False,indent=2))

if __name__=='__main__':main()
```

### 25.4.3 实际结果

| 调用 | 缓存 | 入选ID | 均值 | 状态 |
|---|---|---|---|---|
| 首次cutoff=3 | 否 | a、b | 2 | LOW |
| 再次cutoff=3 | 是 | a、b | 2 | LOW |
| cutoff=8 | 否 | a、b、c | 4 | HIGH |

SQLite完整性检查返回ok；它检查数据库结构，不证明业务数值正确。首次与重试清单哈希相同；不同截止得到不同配方。具体哈希依赖源文件字节和环境，不应把教材中某台机器的摘要作为所有环境统一预期。

10项测试通过：键排序、重复调用、PIT、失败回滚、损坏拒绝、输入改动、未来行变化但过去输出不变、新数据库独立复算、空集未知、非法输入。失败注入发生在写产物后且提交前，验证产物及边回滚，而FAILED尝试记录保留。

### 25.4.4 明确限制

本例只面向单进程；唯一索引能约束成功记录数量，却不是完整多工作者锁。并发竞态、锁重试、租约和崩溃遗留RUNNING尚未实现。事务原子性不等于实际断电测试已经完成。

verify校验清单引用的字节及原始输入、代码链接，不独立证明每个结果按配方正确计算；这由独立重算和业务测试补充。数据库可被具有写权限的人直接修改，因此不是防恶意篡改系统。

配方记录Python、SQLite及固定十进制上下文，不声称冻结全部操作系统、SQLite编译选项或磁盘行为。代码只涉及当前文件；扩展成多模块时必须哈希全部代码依赖，不能继续只取一个入口文件。

本例没有完整修订链，输入视为上游已规范化记录；未来非法行也会触发全输入校验失败，生产应在入口隔离坏消息。金额或收益语义、资产单位、来源真实性不能由SHA-256验证。

存储所有产物会增长。应按保留策略和引用闭包清理本任务产生的临时文件，原始输入、审计和仍被模型引用的快照不能随意删除。教材检索优先在线，仅保留必要链接和笔记。

## 25.5 综合流水线：局部重算、崩溃恢复和跨运行追溯

此处复用第23章原始人工输入和第24章嵌套验证函数。[完整流水线脚本](./code/ch25/dag_lab.py)读取fusion.json里的raw，重新计算特征，而后调用同一个evaluate入口。它另有行情覆盖检查，只依赖原始报价清单。主图为原始文档、报价及标注 → 融合特征 → 验证报告，报价还分出独立行情覆盖步骤。对比不同外层窗口或一份新闻输入修正时，可以独立看到每一步是否重算。

```powershell
& 'D:\Anaconda\python.exe' -X utf8 教材/code/ch23/fusion_lab.py
& 'D:\Anaconda\python.exe' -X utf8 教材/code/ch25/dag_lab.py '刚才生成的 fusion.json 完整路径'
```

**从配方到一次成功发布**

配方包括阶段名、直接依赖的内容哈希、参数、当前脚本和相关实现文件的摘要以及Python、NumPy与SQLite版本。底层复用本章的canonical、put和read。首次提交RUNNING记录时登记配方正文；计算完成后以一个事务同时写结果、清单、依赖边、SUCCESS。这样读取者只选SUCCESS，就能避开未完成的尝试。缓存命中先检查输入摘要对应的字节，再校验配方和输出。内容身份保持可用于下游，运行ID则区分实际执行尝试。成功请求表允许新的请求重用旧阶段运行，并可引用前一验证请求。

练习先画三个阶段的直接依赖，再从验证输出沿edges反向查询。递归SQL每步找child等于已有摘要的边，只经过SUCCESS运行，UNION消除重复摘要。此次恢复报告闭包包含验证输出、验证配方、融合特征、融合配方、原始快照五个节点。行情覆盖是另一个终点，没有出现在验证报告的闭包。若把新闻原文误挂到行情检查的依赖里，单独改原文也会不必要地重算行情检查。

**在事务提交前结束进程，再从磁盘恢复**

脚本在自己新建的数据库中先完成三个外层窗口。接着子进程运行不同评价配方，只保留前两个窗口。新验证写完产物和边后，通过os._exit在提交前退出。父进程等子进程结束并检查退出码，再重连数据库，验证遗留RUNNING无成功清单且没有相关边。随后将该状态标记为FAILED及INTERRUPTED。父进程持有这个临时数据库的独占操作权。若部署多个工作者，应增加租约和令牌，不能直接把所有RUNNING改成失败。[SQLite原子提交及回滚](https://www.sqlite.org/atomiccommit.html)

恢复后重跑未完成请求。融合特征、行情覆盖已经存在，均命中缓存，只有新配方的验证重算。再次请求全部命中。实测SQLite结构检查为ok，记录一条中断。这个故障在教学数据库中实际发生，覆盖进程中断和事务边界。磁盘损坏、断电、网络分区、多机竞态仍需另做演练。

| 请求 | 融合特征 | 行情覆盖 | 验证 |
|---|---|---|---|
| 初始三个外层窗口 | 计算 | 计算 | 计算 |
| 两窗口请求恢复 | 复用 | 复用 | 重算 |
| 再次提交两窗口 | 复用 | 复用 | 复用 |
| 同样两窗口，改一条新闻 | 重算 | 复用 | 重算 |

新闻修改构造另一份人工输入，不在原快照上覆盖。行情覆盖的直接输入仍是相同报价清单，因此命中。融合输出保存全量新闻审计，即使很晚的修改对较早验证折的预测值无影响，融合对象身份仍可以改变，验证会保守重算。生产可让验证配方仅依赖所用的分区快照以缩小重算范围，但必须将成熟标签、模型版本和清洗规则也列入依赖。

**验收题**

1. **手画血缘。** 删除融合产物的一个引用前，找出哪些发布结果仍依赖它。**参考** 从原始对象沿边向前找融合及验证，再检查成功请求是否仍引用这些结果。行情覆盖走报价分支。存在仍保留的验证请求时不可回收融合产物。
2. **验证局部重算。** 只修改验证参数时列出缓存编号是否变化。**参考** 同一融合及行情覆盖阶段复用相同运行ID，新验证得到新运行ID，最初三折报告仍可独立读取。两折报告的前两折内容逐项等于原报告中的前两折，验收不能只比最终均值。
3. **设计恢复升级。** 模拟提交后但回应前断线。**参考** SUCCESS和结果已提交，重试应匹配相同配方并核对结果字节。若有通知副作用，提交时将去重键和待发送事件一起写入事务发件箱。验收分为提交前结果不可见、提交后重试无重复发布、上游未改时不重算、所有尝试可追溯。

## 本章总结

可复现系统依赖完整输入、明确时间语义、版本化代码参数和环境，而不是单独一个随机种子。内容身份支持校验和缓存，血缘支持追溯，事务支持完整发布，各自承担不同职责。只有将它们与独立测试和失败恢复组合，才能可靠回答“这个市场状态是怎样产生的”。

## 分层练习题

1. 概念：为什么运行ID、计算键和结果哈希不能共用一个字段？
2. 推导：N个b位均匀哈希对象的碰撞上界怎样得到？它是否证明数据真实？
3. 时间：改变ready=8记录的值，cutoff=3的输入快照键、均值和清单应怎样变化？
4. 事务：产物写完但SUCCESS提交前失败，哪些内容应可见？
5. 数值：绝对容差0.001、相对容差0.01，a=100、b=100.5是否通过本章容差？若阈值100.2呢？
6. 编程：将已保存原始产物改坏，验证缓存路径拒绝返回。
7. 复现：缓存命中与新数据库重算有什么区别？为什么两者都需要？
8. 版本：宏观值修订后重新计算，如何保留旧在线报告？
9. 故障：进程被杀后RUNNING永久保留，应怎样恢复而不重复产生业务副作用？

## 详细参考答案

### 题1

运行ID区分尝试；计算键区分完整计算请求；结果哈希区分字节内容。同请求可失败后多次尝试，不同请求也可产生相同结果。混用会丢失失败历史，或阻止合理内容去重。

### 题2

共有N(N−1)/2个无序对象对，每对碰撞概率2的−b次方，用联合上界相加得N(N−1)/2的b+1次方。上界很小时可近似理解风险量级，但不能证明输入来自权威来源；攻击者替换可信根也不受普通摘要保护。

### 题3

原始字节改变，输入哈希和计算键改变；新清单引用新的原始对象，因此清单哈希也改变。截止3仍只选a、b，均值2及LOW不变。输出内容哈希可以相同，这体现来源身份和计算结果不是同一概念。

### 题4

本例同事务中的产物、边及SUCCESS均回滚，消费者不能看到成功半成品。先前已提交的RUNNING记录可见；可捕获异常时再标FAILED。真正进程死亡不保证会执行FAILED更新，需恢复任务处理。

### 题5

误差0.5，容差0.001+0.01乘100.5=1.006，所以数值验收通过。但100低于100.2，100.5高于100.2，业务决策不同。因此仍需单独校验阈值和状态，必要时引入业务认可的边界政策。

### 题6

在code/ch25目录执行，使用内存库，不修改已有运行：

```python
from lineage_lab import connect, pipeline, sample, digest
db = connect(':memory:')
pipeline(db, sample(), 3)
db.execute('UPDATE artifacts SET body=? WHERE hash=?', (b'broken', digest(sample())))
db.commit()
try:
    pipeline(db, sample(), 3)
except ValueError:
    print('corruption detected')
else:
    raise AssertionError('corruption not detected')
finally:
    db.close()
```

校验失败后不能自动覆盖旧对象；应隔离、调查并从可信副本恢复。测试验证偶发损坏检测，不证明对管理员恶意改写免疫。

### 题7

缓存路径证明旧结果仍完整可读取，独立重算证明给定依赖能重新产生相同结果。缓存一直返回旧值可能掩盖依赖丢失或代码已无法运行；重算不检查缓存则可能漏掉存储损坏。仍需独立手算验证业务正确性。

### 题8

旧报告固定原始版本、知识截止和清单。新修订生成新快照及重算运行，关联旧运行并标明修正原因；latest指针可更新，但旧报告引用不得悄悄替换。原样回放和最新知识研究分别展示。

### 题9

记录心跳/租约，到期后由恢复任务确认执行者失效，再创建新尝试。用隔离令牌阻止旧工作者恢复后提交，成功发布有唯一业务键，外部通知经事务发件箱及接收端去重。不能仅因RUNNING很久就让两个工作者同时无约束写入。

### 题10

对象存储写不可变内容，元数据库保存清单和原子发布指针。消费者只读已发布版本，孤儿对象按引用闭包及宽限期处理。角色分离写入、发布与审计权限，可信摘要或签名独立保管。原始数据许可、敏感信息和模型快照保留期限分别管理。

验收包含PIT、重试、并发冲突、提交前后故障、对象缺失/损坏、旧版本重放、权限拒绝、独立重算及副作用去重。评分参考版本时间25、事务恢复25、血缘复现25、安全保留15、成本10。画出流程但不能注入故障验证，不算完成。
